# 0.1.4 单条彻底删除与桌面操作契约

状态：2026-11-11 经维护者确认，替代旧基线中“不提供永久删除”的范围限制。实现和实际验证另见版本验证记录；协议升级为 protocol_version=2，HTTP 路径仍为 /v1。

## 1. 删除范围与承诺

- 仅对回收站的单条笔记提供确认后的“彻底删除”。不提供批量清空、自动清理或定时清理。
- 本机空间只影响本机。同一服务器账号中的同一 note_id 在设备联网同步后收敛到永久删除。独立副本、冲突副本、其他空间及已导出文件不级联删除。
- 成功后应用不可恢复，不出现在列表、搜索或后续导出中。当前正文清空，保留 ID、版本及永久删除状态以阻止复活。不承诺磁盘安全擦除或立即释放空间；既有不可变 changes、迁移副本、恢复空间、备份和用户导出不追溯清理。
- 其他端尚未联网前可能仍显示旧内容。收到永久删除状态后，不再保存或自动生成该笔记的冲突副本；未提交输入仅留救援缓冲，由用户主动复制或另存新 ID。

## 2. 本地请求与并发

- UI 先 flush，按 profile_id、note_id、expected_generation 请求 core 的 purge。正常笔记、只读空间、过期代次不可请求。
- 本机或从未冻结上传的账号新笔记可以本地完成。其他账号笔记先持久化 purge_requests，返回 purge_state=pending；条目显示“待彻底删除”，禁止编辑、恢复和重复请求，后续导出排除它。
- 请求绑定申请时的权威回收站版本。若普通删除仍在 outbox 中，先可靠确认原操作，再将它确认的删除版本绑定到请求；不得使用随后拉取的新版本自动提高基准。
- 待确认的普通删除若已发生冲突，沿用普通删除规则保全副本，并取消原笔记的彻底删除请求；不得迁移到冲突副本继续删除。
- 退出、重启、断网、注销和空间切换均保留请求及原账号归属。网络及临时服务错误按原 op_id 重试。
- 服务端仅在当前仍为回收站且 rev 等于 base_rev 时接受。其他端已恢复或修改则返回 PURGE_CONFLICT，不创建副本；本地取消请求、刷新权威内容并显示“彻底删除未执行”。成功后所有旧编辑/恢复返回 NOTE_PURGED，不生成副本。
- 结果未知时保留请求；Pull 先见永久删除即完成本地清除。永久删除优先于未确认的旧 outbox，清除旧待发并保留最小标记，不能复活。永久失败须可见，不能误报成功。

## 3. 线协议与存储

- 所有客户端先核对 protocol_version=2。sync push/pull、events、export 和 purge 请求携带 X-Memo-Protocol: 2；服务端拒绝不兼容请求为 PROTOCOL_UNSUPPORTED（426）。旧客户端必须升级，禁止混用；服务端更新需部署后才能使用账号同步。
- Note 增加 purged 布尔值；永久删除快照必须 deleted=true、purged=true、content=""、conflict=null。状态不可逆，原 ID 永不重用。
- POST /v1/notes/purge：请求 {epoch,op_id,note_id,base_rev}，UUID/counter 规则沿用现有协议。成功返回 {epoch,note}，已永久删除的新请求返回同一最终 note。原 op_id 和规范化参数重试返回原成功结果，复用不同参数返回 OP_ID_REUSED。
- 服务端账号授权、epoch 检查、版本检查、正文清空、rev/seq 分配、changes 追加与 processed_ops 成功结果同事务，提交后通知。不存在或跨账号返回 NOTE_NOT_FOUND。PURGE_CONFLICT 为 409，NOTE_PURGED 为 409（Push 内为单项 error）。
- 服务端新增版本化迁移；客户端新增版本化迁移保存 purge_state（none/pending/rejected/purged）与持久化请求。保留已发布迁移校验，验证升级、重开和旧程序拒绝高版本库。

## 4. 托盘左右键

Windows 右键菜单不变。左键释放时，隐藏或最小化窗口恢复并置前，可见且未最小化的窗口经既有 flush 屏障后隐藏到托盘（即使被其他窗口遮住）。按可见性和最小化状态判断，避免系统托盘夺焦影响切换。保存失败显示窗口及救援，IME 完成后才隐藏；快速点击和双击不得穿透待处理生命周期。标题栏最小化行为不变。Linux 保留菜单恢复，不依赖不受支持的图标点击事件。

## 5. 桌面笔记列表折叠

编辑区顶部常驻显示/隐藏列表按钮，保留导航。默认展开，偏好仅保存在本机。折叠不销毁编辑器，不改变 documentKey、笔记、正文、撤销、选区、IME、搜索或列表滚动。点击全部笔记或回收站展开列表；空间切换展开以明确归属。折叠时保留当前空间标识、空间导出和恢复按钮的可达性。源码/预览/对照模式均可折叠，普通预览维持现有阅读宽度。处理焦点、无障碍展开状态与最小窗口宽度。

## 6. 必须覆盖的场景

PURGE-01 本机单条删除、重复请求、搜索/导出/恢复排除、重启保持。

PURGE-02 账号离线申请、重启及注销保留、原账号联网完成、另一端收到最终标记。

PURGE-03 申请后另一端恢复/修改，拒绝删除且不误删新内容；不自动抬升基准。

PURGE-04 成功回包丢失、同 op_id 重试、Pull 先见结果，结果幂等。

PURGE-05 永久删除后旧编辑/恢复及冻结 outbox 不复活、不自动创建冲突副本；UI 未保存缓冲可手动救援。

PURGE-06 未确认普通创建/删除先确认再彻底删除；从未发送的删除只留本机。

PURGE-07 账号隔离、设备吊销、epoch、操作 ID 复用、事务回滚、旧客户端拒绝、旧库升级。

原开发轮验证 Windows 与 Android；后续发布轮按维护者要求补齐 Windows、Android、Linux 实际测试，见[发布验证](../docs/releases/0.1.4-validation.md)。同步/迁移独立交叉评审、真实 Go 联调与未运行平台检查必须单独列明，不以客户端构建通过代替。
