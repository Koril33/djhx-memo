# v1 首批验收场景

状态：待实现的测试输入与断言，当前未执行。每例独立初始状态；正文使用精确字面值，下面的 rev/seq 是数值说明，wire 中均用字符串。除特别说明外 N 初始正文为“初始”、rev=1、seq=1、active，同账号两设备 A/B 已拉取此版本，head=1。

## 同步与冲突

| ID | 操作序列 / 故障 | 必须断言 |
|---|---|---|
| SYNC-01 | 空账号；A 以 O1、base=0 创建 N=“甲”；重试 O1 两次 | N rev=1，head=1，只有一条 change；三次结果相同 |
| SYNC-02 | A/B 离线改 N 为“甲”/“乙”；A 先 push base=1，B 后 push base=1 | N=“甲” rev=2 seq=2；副本=“乙” rev=1 seq=3；来源 B；所有端最终可见两份 |
| SYNC-03 | A push 服务端已提交但响应丢失；客户端重启后原 O 重试 | 只一次实体变化和幂等结果，无重复副本；outbox 最终完成 |
| SYNC-04 | A 本地改“甲”基准 1；B push“乙”成 rev=2；A 先 Pull 后 Push | A 仍以基准 1 发送，发生冲突；不能因 Pull 把本地基准抬高而覆盖“乙” |
| SYNC-05 | A 冻结“甲”代次 G 并发送；响应前本地保存“甲乙”代次 G+1 | 确认 G 后仍保留 G+1；下一操作基于已接受 rev，最终为“甲乙” |
| SYNC-06 | B 已改原笔记；A 冻结“甲”后继续写“甲乙”，收到 conflict | 原笔记不变；“甲乙”留在冲突副本且可继续推送，焦点/ID 映射不丢；重启后映射仍在 |
| SYNC-07 | A 删除 base=1 成墓碑 rev=2；B base=1 推送“新内容” | 原 N 保持墓碑；active 副本保留“新内容”，reason=edit_after_delete |
| SYNC-08 | A push“新版”成 rev=2；B 以 base=1、deleted=true 推旧内容 | 原 N 仍 active“新版”；旧内容形成 active 冲突副本；显示删除未执行 |
| SYNC-09 | A 已删除 N；B 以不同 O、旧 base 再删，正文与墓碑相同 | already_deleted，rev/seq/head 不增加；未创建无意义副本 |
| SYNC-10 | A 恢复已知墓碑，base 与当前相同 | 原 ID 恢复 active，rev+1；所有端收敛，正文保留 |
| SYNC-11 | 新建从未冻结发送的本地笔记，离线删除，再恢复 | 删除阶段只在本地回收站；恢复后创建一次云笔记，不伪造已上传状态 |
| SYNC-12 | 创建请求已提交但响应丢失；A 随后本地删除并重启 | 先按原 O 确认创建，再发送删除，服务端最后为墓碑；无孤立 active 笔记 |

## 分页、事务与错误

| ID | 操作序列 / 故障 | 必须断言 |
|---|---|---|
| SYNC-13 | changes 为 seq1～5，首个页面 limit=2、H=5；随后服务端追加 seq6 | 本轮依次 cursor2、4、5，until 始终 5；下一轮读到 6；旧页快照不可变 |
| SYNC-14 | 应用一页期间，在更新正文后、推进 cursor 前注入崩溃 | 正文、shadow、cursor 一起回滚或一起提交；重开重读不漏项 |
| SYNC-15 | 新设备 cursor=0 分页时新增本地笔记，并收到并发远端编辑 | 本地新笔记保留，拉取全部 H 内变化，后续推送不覆盖已有远端 ID |
| SYNC-16 | 同 O 第一次发送“甲”，第二次发送“乙” | 第二次 OP_ID_REUSED；无新版本/副本/seq |
| SYNC-17 | 请求含成功 O1、字段不合法 O2、成功 O3；提交 O1 后进程中断并整体重试 | O1 仅一次；O2 error 无副作用；O3 最终一次，结果顺序与请求一致 |
| SYNC-18 | 单项事务在写 notes 后、写 changes/processed_ops 前故障 | 全部回滚，重试只提交一次；不得出现实体已改但日志/幂等结果缺失 |
| SYNC-19 | base_rev 大于当前；或 N 不存在但 base>0 | INVALID_BASE_REV / NOTE_NOT_FOUND；正文与操作保留，不自动新建 |
| SYNC-20 | cursor>head、until<cursor 或非法计数字符串 | CURSOR_INVALID/INVALID_REQUEST；不静默跳到 head，不清库 |
| SYNC-21 | SSE 全丢/重复、断线重连、Push 后通知前崩溃 | 30 秒前台兜底最终同步；通知不直接改 cursor，重复信号不产生操作 |
| SYNC-22 | 响应 429/503/超时后恢复网络 | 按 Retry-After/退避重试，冻结内容与 O 不变，手动重试不并发发送 |

## 账号、本机空间与恢复

| ID | 操作序列 / 故障 | 必须断言 |
|---|---|---|
| AUTH-01 | 两账号使用相同 N/O；尝试拉取、推送、导出、吊销对方设备 | 数据完全隔离；跨账号资源视为不存在；用户序号独立 |
| AUTH-02 | B 吊销 A；A 离线写笔记后联网 | A API 被拒绝、SSE 关闭；本地正文/outbox 仍在；重新登录后继续处理 |
| AUTH-03 | 一次邀请码并发两次注册；其中一个注册响应丢失 | 只一账号消费成功；无部分用户；合法账号可通过登录取回会话 |
| AUTH-04 | A 空间任务排队，切换 B 后旧任务执行/回调 | 凭据和结果仍绑定 A，不能写入 B 或把 A 正文上传给 B |
| AUTH-05 | 退出时有待发内容且无网络；之后重新登录原账号 | 内容与操作保留；退出不误报远程已吊销；新凭据不会导致新操作重复 |
| LOCAL-01 | 本机空间离线创建、重启、搜索、删除恢复和导出 | 全部可用，无账号/网络请求前置条件 |
| LOCAL-02 | 导入部分本机笔记后崩溃，重复导入同一源代次 | 目标事务和映射一致；同账号无重复，来源仍在；另一个账号映射独立 |
| LOCAL-03 | 保存事务磁盘满/权限不足，随后恢复可写 | 不显示已保存，缓冲可复制救援；成功重试后内容一致 |
| LOCAL-04 | 系统凭据库不可用，退出后重启 | 不写明文 token，提示重新登录；笔记仍可本地访问 |
| LOCAL-05 | 旧 UI 以 expected_generation=G 保存，而 core 已为 G+1 | LOCAL_GENERATION_CONFLICT；两份内容受保护，不盲目覆盖 |
| LOCAL-06 | 创建已提交但 UI 响应丢失，以相同本地请求 ID 重试 | 仅一条本地笔记、同一 note_id；不会生成两个云端创建操作 |
| RECOVERY-01 | 客户端 cursor=10，服务端恢复 head=5 并轮换 epoch；旧 Push 重试 | Push 无副作用；旧库保全，重新拉取新副本；旧内容按选择以新 ID 导入 |
| RECOVERY-02 | epoch 相同但 cursor 超前或数据异常 | 进入安全恢复流程并记录诊断，不将 cursor 改为 0 后自动重放原 outbox |
| MIGRATION-01 | 上版数据库含本地待发、冲突和墓碑，升级中断 | 升级成功完整保留；失败可恢复；高版本库不被旧应用降级 |

## 编辑器与平台

| ID | 操作序列 / 故障 | 必须断言 |
|---|---|---|
| EDIT-01 | 查询“会”“会议”、ASCII 大小写、引号、百分号和类似 SQL/FTS 的文本 | 字面匹配一致，短词命中；不解释为语法或注入；不返回回收站 |
| EDIT-02 | 中英文混输、长文粘贴、emoji、换行；编辑中收到远端变化 | 输入法组合不被中断；已提交内容逐字一致，换行 LF；本地草稿受保护 |
| EDIT-03 | 任务列表与代码块内相同文本、旧预览后再编辑并点击 | 只修改最新对应任务标记，代码块不变；旧预览不能覆盖新代次 |
| EDIT-04 | 正文包含 script、原始 HTML、外部图片、危险链接协议 | 无脚本/隐私外联执行，无 Tauri 命令访问；安全链接交系统浏览器 |
| EDIT-05 | 超 1MiB 正文，本地或服务端拒绝 | 不截断；保留可救援内容，其他笔记同步不受阻 |
| PLATFORM-01 | Windows/Linux 关闭窗口、托盘打开/新建/同步/退出 | 保存后隐藏可恢复；退出只等待本地 flush，不等待网络；无后台僵尸进程 |
| PLATFORM-02 | Linux 无托盘支持或初始化失败，Wayland/X11 与中文输入法 | 不把窗口隐藏到无法恢复的位置；解释依赖并能正常退出；目标基线托盘实测通过 |
| PLATFORM-03 | Android 后台、系统结束进程、网络恢复、重开应用 | 已提交数据在，任务不重复推送；前台立即补拉，后台不冒充五秒保证 |

平台与性能的实测记录要求见 [本地验证](../../docs/validation.md)。上述表格不是自动化测试完成证明；实施时逐项关联测试名称或人工验收记录。
