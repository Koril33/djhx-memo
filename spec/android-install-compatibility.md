# Android安装兼容与失败诊断

状态：2026-11-14，PR #21已合并，Android0.1.9单端正式发布；实际状态与API35升级见[发布记录](../docs/releases/0.1.9-validation.md)。不修改已公开0.1.8标签/资产。触发：Xiaomi Civi、Android13、HyperOS1.0.2.0.TKVCNXM，从0.1.7应用内安装0.1.8失败且未见系统确认页；同一官方APK通过浏览器覆盖安装成功、笔记正常。它将问题缩小到应用内交接，不能据此断言厂商拦截或已经知道系统失败码。

Android本次版本为0.1.9/code10；Windows/Linux仍0.1.8，core0.1.7/server0.1.4。构建、公开分发与真机验收分别记录，不能相互替代。旧0.1.8客户端仍执行旧安装流程，失败时可用同证书0.1.9 APK手动覆盖一次；新安装逻辑用于之后由0.1.9发起的升级。

## 安装入口

PackageInstaller会话继续为默认。为已下载的正式候选增加“通过系统安装器安装”兼容入口，不根据品牌自动切换，不静默重复弹窗。两条路径都重新验证实时发行目录、候选身份、SHA256/大小、原证书、严格递增versionCode、ABI/minSdk，并在交接前完成编辑持久化与core安装屏障。

兼容入口把校验后的APK复制至应用私有cache专用目录，再次核对大小/哈希，使用非导出FileProvider生成content URI，以ACTION_VIEW和APK MIME交给系统。只授予该文件的临时读取权，不使用file URI、公共存储、宽路径/prefix授权或安装权限绕过。复用已锁定AndroidX Core，不新增运行时依赖。

每次交接先持久记录独立attempt UUID、目标versionCode与模式，文件名和Activity Result关联键均绑定该attempt。迟到回调不能解除新尝试屏障或撤销新URI；已存回调键在Activity创建时恢复注册，不依赖原Activity对象。明确终态后恢复编辑并撤销该文件URI授权；ACTION_VIEW/EXTRA_RETURN_RESULT不保证结果码可靠，版本未达到目标时标为结果未知，保留等待并提示先关闭系统安装页再“取消等待”，不宣称能撤销外部安装。进程重启按系统实际versionCode核对：到达目标才记成功，不能因回到前台或RESULT_OK就虚报成功。仍需原来源授权与系统用户确认，来源授权页本身不持安装屏障。

## 失败诊断

保留PackageInstaller固定状态分类：系统阻止、安装冲突、包无效、设备不兼容、存储不足、用户取消、超时和未知失败。使用固定本地化提示；只持久化允许的固定错误码，不显示/记录原始状态消息、Intent、APK路径或笔记/凭据。失败回包不能被统一UPDATE_INSTALL覆盖；重开页面/进程后仍可查看最近分类，新的手动检查/安装清除旧失败。

系统确认Intent在存活进程中保留完整对象，不能先转URI再解析而丢掉Parcelable等附加信息；重启后没有完整对象的旧会话仅保留取消/重试，不将旧URI当成完整Intent恢复。

撤销授权、删除暂存、安装记录写入或原生失败状态记录异常不能跳过core恢复。保留私有清理票据并显示“恢复更新状态”重试入口；core恢复本身失败也保留重试，不误报编辑已恢复。恢复完成前拒绝新安装，不把缓存清理失败当笔记已损坏。专用路径以应用cacheDir的canonical根限制，接受Android合法父路径别名，拒绝逃出专用目录或叶子符号链接。

持久记录完成后重新获取当前Activity，紧邻交接核对其仍至少STARTED且未finish/destroy；后台或旋转留下的旧Activity不得继续启动安装页，固定提示后清理并恢复。不能跨IO挂起保留旧Activity作为最终交接对象。

## 验收

检查原会话路径、固定状态分类与重启保留、取消后编辑、私有URI读权限/路径范围、复制篡改拒绝、来源授权、兼容安装确认及新进程真实版本/原ID正文保留。AOSP模拟器与Civi真机分别记录；手动浏览器覆盖成功不冒充应用内兼容入口已验收。core/server/协议/schema不变，完整设备矩阵仍未完成。
