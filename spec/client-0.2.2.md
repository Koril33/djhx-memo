# 0.2.2 客户端目标规范

- 日期：2026-11-22；状态：**维护者已确认产品范围，开发前规范，尚未实施或验收**。
- 基线：`v0.2.1 / 9e4c842`，当前主分支文档提交为 `fd0ea4c`。0.2.1 已公开；发行与测试分别见[发布记录](../docs/releases/0.2.1-validation.md)。
- 实施与验收设计见[开发文档](../docs/client-0.2.2-development.md)。本规范只定义 0.2.2 目标，不把目标写成现有能力。
- 继承 [0.1.13](client-0.1.13.md)、[0.2.0](client-0.2.0.md)、[0.2.1](client-0.2.1.md)、[自动更新](automatic-updates.md)中未被本版明确替代的行为。同步协议、笔记 schema、应用及签名身份不变。

## 1 范围

| 范围 | 0.2.2 目标 |
|---|---|
| Windows 和 Linux | 可选 Markdown 格式检查，默认关闭；对照模式双向按内容同步滚动，默认开启 |
| Linux 更新页 | 维持 DEB 手动安装，提供动态指向最新正式 DEB 的下载入口；不启用自动检查、后台下载或安装 |
| 三端更新页 | 固定提供 `memo.djhx.site` 与 `GitHub` 两个下载源；默认个人服务器 |
| 官网和发行 | 官网主下载使用个人服务器，GitHub 为备用；同一正式安装包在两处逐字节一致 |

本版不增加 Android lint、自动修复/格式化、Linux AppImage/APT/自动安装、自定义下载地址、图片附件或独立 Web 客户端。完整 v1 设备矩阵仍独立验收。

## 2 桌面 Markdown 格式检查

### 2.1 设置和提示

- 设置中增加“编辑器”分组，提供“Markdown 格式检查”，默认关闭；仅保存为本设备偏好，不随账号同步。
- 只检查当前正文，离线运行；只读笔记也可查看提示，但不能由提示修改正文。空白页不启动检查。
- 开启后提供轻量范围标记、问题数量和可按需打开的问题列表；列表显示规则编号、本地化说明和行列，点击定位。隐藏的源码编辑区需要定位时进入源码模式。
- 不弹模态框，不自动展开问题列表，不阻止输入、保存、同步、导入、导出或关闭；检查失败与“没有问题”区分。
- 首版不提供修复动作，不因检查重写正文、行尾、硬换行或标题；提示不是判定笔记有效性的门禁。

### 2.2 调度和规则

- 使用随包离线资源，在独立 Worker 中检查；停止输入后延迟执行，中文 IME 组合期间暂停。关闭开关立即清理提示并停止在途任务。
- 回执绑定空间、文档会话、正文版本及规则版本，切换笔记、关闭或更新正文后拒绝过期结果。
- 超过 128 KiB UTF-8 的笔记暂停实时 lint，显示可手动检查；正文上限仍为 1 MiB。手动检查同样可取消、有超时与结果数量限制，不能锁住编辑或保存。
- 内置规则以本节白名单为准；默认关闭长行限制、强制一级标题、末尾换行等不适合随记的限制。不执行用户 JavaScript、自定义规则或正文中的脚本，不读取工作目录配置。
- 关闭状态不加载 lint 引擎或执行检查；保留现有语法高亮与 M2 性能降级规则。

### 2.3 首版规则白名单

内置配置为 `default: false`，只开启下表。规则调整属于产品行为修订，须与本规范和回归用例一起修改，不采用版本升级后自动增加的上游默认规则。

| 规则 | 内容与参数 |
|---|---|
| MD009 | 多余行尾空格；`br_spaces: 2, strict: false`，合法双空格硬换行不报错 |
| MD018 / MD019 | ATX标题符号后缺少空格或空格过多 |
| MD023 | 标题行不必要缩进，保留代码与嵌套上下文语义 |
| MD037 / MD038 | 强调/行内代码边界内不必要空白 |
| MD039 | 链接文字边界内不必要空白 |
| MD042 | 空链接目的地址 |

MD013长行、MD025/MD041一级标题、MD047文末换行及其他未列规则全部关闭。开关仅控制这些检查，不改变现有渲染安全规则。

## 3 桌面对照模式同步滚动

- 本设备“对照同步滚动”默认开启，设置与对照工具栏开关共用同一偏好；退出对照模式只暂停同步，不改开关值。
- 用户滚动任意一侧，该侧成为当前控制方；另一侧按源码位置和预览块的映射跟随。程序触发的滚动不得再次反向触发，用户接管优先。
- 以可视区顶部的对应内容及块内相对位置为基准，支持标题、段落、列表、引用、代码块与表格；不能仅以全文滚动百分比作为常规同步算法。
- 滚动不移动光标、焦点或选区，不标记正文修改，不触发保存。代码块/表格横向滚动保持独立。
- 正文变化、预览重绘、字体或窗口尺寸变化后刷新映射；按同一正文快照使用映射，过期或缺失时暂缓跟随并恢复，不使用旧映射跳到另一篇笔记。
- 同一内容块内允许近似插值，不承诺两侧逐像素对齐。长文只测量所需位置，不能在每个 scroll 事件中遍历全文 DOM 或重新解析正文。

## 4 下载源

### 4.1 选择与状态

- Windows、Linux、Android 的“软件更新”页均显示下载源控件，选项文字为 `memo.djhx.site`、`GitHub`，默认前者；内部值仅为 `memo`、`github`，不接受 UI 传入 URL、文件路径或公钥。
- 选择跨重启持久化、跨账号共用，不随账号同步。旧安装首次升级后也默认 `memo`；无效或损坏的来源偏好回退默认并提示，不清除安全状态。
- 来源仅决定安装包传输位置；检查版本、撤回及安装前复核仍访问固定签名目录 `https://memo.djhx.site/updates/stable/current.json`。选择 GitHub 不代表官网或签名目录全站故障时仍可自动更新。
- 首版不隐式切源。网络失败在页内提供重试和切换到另一来源；哈希、尺寸或签名失败阻止安装，不把切源作为绕过验证的途径。
- 下载中切源取消旧传输并等待原生完成回执，清除半包后允许用户重新下载；不自动重启下载。等待期间可返回、切页和编辑，不能同时运行两次传输。
- 已验证完整缓存可跨来源复用，仍按同一资产身份重验；切源不重置目录序号/摘要、不清除稍后版本、不取消已提交安装会话。准备安装及系统交接期间禁用来源切换。

### 4.2 安装包与旧客户端兼容

- 固定个人服务器路径为 `https://memo.djhx.site/downloads/releases/<tag>/<asset>`；GitHub 路径继续为本仓库版本化 Release 资产。
- 保持现有 v1 签名目录的字段、GitHub 规范地址、信封和序号规则。0.2.2 在验签及目标校验后，以内置信任规则把合法 GitHub 资产身份映射为个人服务器路径；实际收到的文件仍必须匹配签名目录中的版本、大小、哈希及平台签名。
- 该映射只允许本仓库、正确 tag 和本平台标准文件名；不能使用自由文本替换 URL、任意镜像域名、跨站代理或通配后缀信任。
- 个人源的自动下载要求固定 HTTPS 主机、标准端口、无 userinfo/query/fragment 及固定路径；首版不跟随其重定向。GitHub 仅允许既有受信资产域名的有界重定向。两类请求不携带账号凭据。
- 旧客户端仍从原目录获得 GitHub 地址，照旧下载 0.2.2；0.2.2 安装完成后才具备主源和切源能力。GitHub 不可达的旧客户端需从官网手动覆盖安装一次，不修改原包名、证书或安装目录。
- 保留 Windows Tauri 更新签名和 Android 原证书/包名/versionCode/ABI 校验；本版不调整冻结的兼容字段或实现跨 schema 更新。

## 5 Linux 最新 DEB

- 更新页继续显示“手动更新”，提供“下载最新 DEB”，在系统浏览器中打开，不在应用内下载、提权安装或自动重启。
- 个人源入口为 `https://memo.djhx.site/downloads/latest/djhx-memo-linux-amd64.deb`，由服务器以短缓存的临时跳转指向已验证的版本化 DEB。
- GitHub 入口为 `https://github.com/Koril33/djhx-memo/releases/latest/download/djhx-memo-linux-amd64.deb`。自 0.2.2 起，每个适用正式 Release 额外附加同名 DEB 别名，内容与该 Release 的版本化 DEB 完全相同，并列入 SHA256SUMS。
- “最新”指已公开、非预发布、已验收且未撤回的适用 Linux amd64 发行物，不是应用自身版本或构建时间。非 amd64 环境明确提示不支持并提供下载页，不静默下载错误架构。
- 撤回时同步调整两个latest入口到安全适用发行物，无安全目标则暂停入口；不改写旧版本文件，也不改变自动更新的禁止降级与目录单调规则。
- 安装仍由用户及系统工具完成；两个按钮成功打开浏览器不等于下载完成或升级成功。用户自行继续编辑，不进入安装保存屏障。

## 6 官网与发布

- 官网各下载入口默认个人源，同时提供 GitHub 备用直链；语言/主题和 JavaScript 开关不改变或覆盖生成后的下载地址。
- 安装包与 `.sig`、SHA256SUMS 使用独立、持久的只读文件区，不随官网发行目录轮换而删除。草稿包仅私有暂存，不可先暴露到正式下载路径。
- 保留 GitHub Actions 构建签名及 Release 草稿，保留维护者部署服务器的权限边界；CI 不新增生产服务器 SSH 凭据。
- 正式推广前，两源同包核验、个人源就绪、Linux 别名验证、目录验签和兼容旧更新器均须通过；先文件、后索引/最新入口/官网和签名目录，失败保持旧版本可用。
- 下载限流/资源预算只作用于下载路径，保留 `/v1`、SSE、`/healthz` 的现有行为。下载源切换和部署均不能重置防回放或回退已接受的目录序号；撤回需更高序号及明确的修复策略。
