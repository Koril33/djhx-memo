# 0.1.6 列表操作与单文件 Markdown 导入

- 状态：维护者已接受的下一版本规范，2026-11-13；**尚未实现、未验收**，不属于 0.1.5 安装包。
- 范围：Android 多选/左滑；Windows/Linux 对应多选批量操作；三端普通删除快捷撤销、单个 Markdown 文件导入。Web、批量彻底删除、自动清理、文件夹/ZIP/多文件导入继续暂缓。
- 仍以[删除契约](permanent-deletion.md)、[同步协议](sync-protocol.md)和[产品基线](product-v1.md)裁决数据状态；客户端不得用时间或列表位置覆盖新版本。

## 1. 多选与批量移入回收站

Android 长按一条进入多选并选中首项；后续点击切换选中状态，不打开编辑器。顶栏显示已选数量、取消和 trash 图标；零项时禁用删除。返回先退出多选。桌面提供明确的选择入口/复选框，可支持 Ctrl/Cmd 点选及 Shift 范围选择，不依赖长按或鼠标拖拽。

选择绑定 `profile_id + note_id`，不绑定列表索引。只操作当前空间和当前普通列表；全选作用于当前搜索/筛选结果，不包含隐藏的回收站或其他空间。列表刷新按稳定 ID 保持仍有效的选择；切换空间/账号/回收站或改变搜索条件时退出多选。旋转/布局变化保留同一空间的选中 ID。

core 提供批量普通删除入口，逐项检查可写状态、代次和永久删除屏障，持久化后才报告成功；返回逐项结果，界面显示成功/失败数量，失败项保留可重试。当前编辑目标在批次中时先完成 IME/编辑持久化，保存失败不移走该目标或丢弃缓冲。批次不承诺跨设备原子可见，继续通过既有逐笔同步收敛。

批量 trash 只设置普通删除状态，保留正文。此版不提供回收站批量彻底删除或批量清空。

## 2. Android 左滑移入回收站

仅普通列表、非多选、可写空间启用。左滑露出红色背景和 trash 提示；位移按条目宽度计算，**达到约 50% 且松手后**提交，未达阈值回弹；快速短甩不能绕过距离门槛。阈值为本产品默认值，落地以真实触控验证为准。

区分水平滑动、纵向滚动和系统边缘返回；未确认手势前不得抢占滚动。达到阈值可提供适度触觉/视觉反馈。失败时恢复条目与可重试状态，不能只移除界面而不写入 core。回收站内禁用此手势，不把同一操作变成彻底删除。桌面保留按钮/菜单，不要求模拟触控滑动。

## 3. 普通删除的快捷撤销

多选或左滑删除成功后显示非阻塞提示“已移入回收站 N 条 · 撤销”；约 8 秒默认展示，遵守系统无障碍超时。提示期间连续左滑的成功项并入当前组并刷新计时；一次批量操作整体构成一组。只保留当前提示组，不建立无限历史。

撤销目标记录原空间、成功删除的稳定 ID 和删除后代次；只恢复本次成功项，不按当前选中项或列表位置推断。切换空间/账号时关闭快捷提示，不跨账号暗中执行；回收站仍可正常手动恢复。

撤销是新的持久化恢复操作，离线可提交，联网后同步。不能删除或篡改已冻结待发送操作，不能以“尚在提示期”为由延迟本地删除落盘；其他设备可能短暂观察到删除后再恢复。遇到新代次、冲突、吊销或永久删除，沿用 core 校验，明确逐项结果，不覆盖新正文、不复活已永久删除的原 ID。

提示过期仅关闭快捷入口，笔记继续保存在回收站。普通删除可以取消逐次模态确认，依靠明确手势/选中数量与撤销；单条彻底删除仍单独确认且不可撤销。该撤销独立于编辑器文字 Undo。

## 4. 单个 Markdown 文件导入

三端提供“导入 Markdown”入口，每次仅选择一个 `.md` 文件（扩展名大小写不敏感）；不读取文件夹、ZIP、多文件、Front Matter 元数据或外部附件，不把相对图片/链接对应的本地文件自动导入或上传。渲染继续遵守安全 Markdown 边界。

目标为用户当前可写空间，选择器返回后再次核对原目标空间与可写状态；若空间/账号已切换则停止并要求重新选择目标，不自动导入新账号。账号空间提示导入后会同步；本机空间保持仅本机。未登录可导入到本机。恢复只读空间不可直接写入，可先切换到本机/账号空间。

仅支持 UTF-8（允许 BOM），CRLF/CR 统一为 LF；不猜测 GBK 等编码。按流限制读取，去 BOM/统一换行后正文 UTF-8 字节数不得超过现有 1 MiB 限制，原始输入也设有有界上限（最多 2 MiB + 3 字节，容纳全 CRLF 与 BOM）。超限、非法 UTF-8、文件失效、权限不足或读入失败不创建半条笔记、不改变现有编辑缓冲；纯空白文件提示内容为空，不创建记录。

保留文件内全部 Markdown 文本（仅上述编码/行尾规范化），不把文件名插入正文，也不把第一行挪出正文；标题继续由首个非空行派生。导入生成新的 UUID，与源文件/导出清单原 ID 无绑定关系；不覆盖任何已有笔记。重复手动导入同一文件会创建独立副本，此版不做内容去重或目录镜像。

操作开始时捕获一次导入请求 ID；选择器重复回调、持久化成功后回执丢失的重试不得重复创建。文件内容与新笔记创建交给 core 持久化，账号待同步规则与正常新建一致，不由 UI 写数据库。导入成功后打开新笔记并提示目标空间；当前编辑若不能安全保存则先保留并处理，不以导入替换未保存内容。

## 5. 验收要求（均待执行）

| 场景 | 期望 |
|---|---|
| 长按/返回/旋转、搜索与列表刷新 | 稳定 ID 选择正确，无跨空间误删 |
| 全选、部分失败、重复点击 | 数量准确，成功落盘，失败可重试，无永久删除扩展 |
| 49%/50%附近、短甩、纵滚与边缘返回 | 阈值与松手时机正确，不误触 |
| 多选与连续滑动后撤销 | 只恢复对应组，离线/已同步均按正常规则收敛 |
| 撤销期间远端编辑/已恢复/彻底删除 | 不覆盖新内容、不复活原 ID，逐项结果可解释 |
| UTF-8/BOM/CRLF、中文/emoji/代码块 | 规范化后逐字保留，标题按现有规则派生 |
| 超限、非法编码、空文件、权限撤回 | 无半条记录、无缓冲丢失、固定可操作提示 |
| 文件选择期间切空间/注销、重复回调 | 不导入错误账号、不重复创建 |
| 三端重开及账号同步 | 内容持久，既有冲突/迁移/鉴权规则保持 |

上述为未来实现和验收契约，不将规范入库、静态检查或已有版本测试当作 0.1.6 已完成。
