# 三端自动更新提案

- 状态：**方案提案，尚未实现、部署或验收**；2026-11-11。
- 本轮范围：调研与设计。现有 0.1.3/0.1.4 客户端的运行行为不因本文改变，不预定实现版本号。
- 依据：[17 个软件调研](../docs/research/rust-gui-auto-update-survey.md)、[技术设计](../docs/automatic-update-design.md)、[ADR-0016](../docs/adr/0016-automatic-updates.md)。通过后续实现 PR 启用；不把提案加入现有版本的已完成清单。

## U1. 能力与默认策略

这里的自动更新指自动发现、按设置下载、通过平台安装机制升级；首版安装前保留用户确认。三端共用版本信息和可信发行目录，安装适配分开。

| 安装渠道 | 计划能力 | 安装边界 |
|---|---|---|
| Windows currentUser NSIS | 自动检查、后台下载、校验、确认后保存并重启升级 | 保持安装目录、应用标识、现有快捷方式与用户数据 |
| Linux 新增 AppImage | 自动检查、后台下载、校验、确认后替换并重启 | 仅处理本应用且用户可写的 AppImage；权限不足时明确退化 |
| Linux 既有 DEB | 显示新版本、提供匹配 DEB 与安装指引 | 交给系统安装工具；未建设 APT 仓库前不承诺无人值守更新 |
| Android GitHub APK | 自动检查、允许后台下载、校验、确认后交给系统安装会话 | 使用原有包名和签名证书；遵守未知来源授权及系统确认 |

首个带更新器的版本称为 U1，不是版本号。没有更新器的旧客户端必须先手动覆盖安装 U1 一次。DEB 用户可继续原渠道；迁往 AppImage 需要显式选择和验证数据目录，不自动跨渠道切换。

默认开启自动检查：首次可用窗口出现后延迟约 30 秒；其后运行期间约每 24 小时一次，带小幅随机错峰。重新前台时仅在到期后检查；系统挂起/Android 后台限制允许延后，不保证退出后仍定时运行。手动“检查更新”不受 24 小时限制，但同一时刻只允许一个任务。

默认仅在非计费网络自动下载，设置可改为“只提醒”或“允许计费网络”；桌面无法判断计费状态时按计费处理。手动下载给出大小后可继续。关闭自动检查也关闭自动下载，手动检查仍可用。设置属于本设备，不跟随账号同步。

## U2. 界面与非阻塞行为

- 设置/关于增加更新入口，显示当前版本、安装渠道、最后成功检查时间、可用版本、大小、更新说明与进度。
- 提供“稍后”“下载更新”“保存并重启更新”；Android 使用“安装更新”，进入系统流程。下载中可以继续编辑与同步。
- 不要求登录，不上传笔记、账号标识、服务端地址或设备 token；公开更新检查独立于账号服务器。网络服务仍可接收必要的 IP、客户端版本/平台等访问数据，隐私说明必须据实披露。
- 离线、更新服务不可达、签名失败、权限不足不阻止启动和本机记笔记。自动检查失败使用非打断状态；用户手动检查时给出可操作错误。
- 首版只有 stable，不强制退出、不自动重启、不通过更换安装渠道绕过权限。稍后处理按候选版本记录；手动检查能重新查看。
- 更新说明为受限纯文本/安全 Markdown，沿用正文渲染边界，不执行 HTML、脚本或远程内容。

## U3. 保存与安装屏障

“下载完成”不等于“可以立即退出”。每次实际安装前必须：

1. 重新验证候选版本、平台、渠道、签名、兼容性和缓存；撤回的候选不得继续安装。
2. 完成输入法组合输入，提交当前编辑缓冲并等待持久化回执；保存失败或组合输入无法完成时暂停安装，允许继续编辑/救援导出。
3. 原生协调器阻止新的写操作，等待正在进行的数据库事务与同步应用操作到安全点；确认所有已打开空间的数据和 outbox 已落盘，再关闭句柄与后台工作。
4. 保存更新尝试记录并交给平台安装器。不能依赖安装器触发正常窗口退出事件才保存；不能以远端同步成功作为退出前提。

下载阶段不持有这个屏障。Android 跳转授权设置或等待用户决定期间恢复正常编辑；返回后再次执行保存检查。提交安装会话前清除待处理编辑操作并持久化；平台回调和应用重启都必须能恢复状态，不能依赖原进程一直存活。

取消/失败后，仍在运行的客户端恢复正常工作；已经退出时允许启动旧版或经验证的新安装包修复。安装成功只能在再次启动确认实际版本后标记。

## U4. 真实性与版本规则

- 只接受编译时信任公钥验证通过的发行目录，以及其明确列出的平台资产。HTTPS、SHA-256 与操作系统签名各自承担职责，任何一个不能替代完整发行验证。
- 必须校验签名目录绑定的版本、URL、字节数、哈希、平台、架构、安装格式与兼容要求。缓存重用时重新校验，不能只看文件名/“下载完成”标志。
- 桌面同时要求 Tauri 更新包签名并绑定应用版本；Android 同时由系统验证 APK 签名，预检包名、证书、versionCode、minSdk 与 ABI。签名不匹配不建议卸载重装，避免丢失本地数据。
- 稳定通道采用 SemVer 比较，不用字符串排序；Android 还必须严格增加 versionCode。无更高版本不重装；稳定通道不自动安装 prerelease，不跨架构、不自动降级。
- 已接受的发行目录序号单调递增；相同序号只能接受相同原始内容，拒绝序号回退。保护边界不包括本机管理员篡改与新装设备没有历史状态时的完整防冻结，见技术设计。
- 私钥、Android keystore、签名口令、GitHub 写 token 永不进入客户端或仓库。自动更新不能静默接纳远端下发的新根公钥。

## U5. 兼容与恢复

0.1.4 基线为同步协议 2、core 数据库 schema 3、服务端 schema 2。发行目录需描述新客户端支持范围；实际数据库检查和协议握手仍由 core 执行，更新器不得改写这些规则。

首个实现迭代优先覆盖**不改变协议/数据 schema**的升级。后续有兼容变化时，已知不兼容的账号服务器阻止自动安装并说明升级顺序；离线无法确认时不自动安装，可由用户明确选择“升级后暂时离线使用”。本机笔记仍可用，不把公开更新域名当作同步服务。

升级前验证数据备份策略，保留可恢复的本地数据与未发送操作。失败时不自动把旧二进制用于新 schema，也不静默恢复旧数据库丢弃升级后的输入。回退只在确认数据兼容、尚未产生新写入且用户知情时进行；通常优先发布更高版本修复包。

## U6. 平台发布与撤回

- Gitea 继续放代码/评审，GitHub Release 继续放公开源码及安装包；官网提供静态可信更新入口，不新增 CI/Runner。
- 每个平台只发布已经构建并验证的资产。Windows 先就绪时可以先推广 Windows；Android/Linux 继续各自已有版本，不显示虚假的可安装新版。
- 已发布 tag/版本化资产不覆盖；增加更高发行目录序号撤回问题版本。已安装问题版需要后续更高版本修复，撤回不是远程卸载或数据库回滚。
- 正式提供“三端自动更新”前，Windows、Android、Linux 各自实际升级链路均须验收；本机只能验证 Windows/Android 不构成 Linux 已通过。

## U7. 后续验收场景（本轮均未执行）

| 场景 | 期望 |
|---|---|
| U-01 未登录、离线、更新服务故障 | 笔记完整可用，重试不阻塞界面 |
| U-02 两窗口/定时与手动同时检查 | 单任务，状态一致，无重复安装 |
| U-03 断网/磁盘满/进程被结束 | 可恢复或重新下载，半包不可安装 |
| U-04 篡改目录/签名/包哈希/尺寸/目标 | 拒绝安装；不退化到无校验流程 |
| U-05 重放旧目录、同序号不同内容、过期目录 | 阻止推广；已有笔记和手动恢复仍可用 |
| U-06 中文组合输入/保存失败/离线 outbox | 先保全输入与操作，失败不退出 |
| U-07 Windows 从历史“简记”目录升级 | 覆盖原安装，无第二套应用；数据和快捷方式正确 |
| U-08 Windows 安装失败/文件占用/杀进程 | 不误报成功，有可执行的修复路径 |
| U-09 Linux AppImage 可写/只读、Wayland/X11、缺 FUSE | 自更新或明确退化，不改写 DEB 文件；运行依赖有说明 |
| U-10 DEB 与 AppImage 共存/单实例/数据路径 | 不并发写同一数据；不擅自迁移或删包 |
| U-11 Android 授权拒绝/取消/后台受限/系统杀进程 | 不丢笔记，能重试，不循环弹窗 |
| U-12 Android 同证书升级、错证书/包名/ABI/versionCode | 正确包保留数据升级；错误包拒绝，真机验证签名连续性 |
| U-13 跨版本协议/schema、不完整平台发行 | 不静默破坏同步或数据，不选错平台资产 |
| U-14 私钥轮换、桥接版本、撤回版本 | 信任链连续；旧客户端得到明确升级/恢复路径 |

除单元测试外需真实下载、签名和平台安装试验。所有测试使用合成笔记、隔离 profile/安装目录、测试签名与测试元数据；不能覆盖维护者日常安装或把测试钥当作生产钥。生产 Android 证书的最终覆盖安装由持钥者在备份后的测试设备确认。
