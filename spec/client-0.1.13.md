## 2. 桌面空白页与会话

### 2.1 状态定义

编辑区须区分 `welcome`（无打开文档）、`draft`（新建编辑会话）、`note`（已打开笔记，含只读笔记）。会话切换中的短暂状态用于串行与输入保护，不是新的笔记类型。

- `welcome` 不创建笔记、草稿行、保存定时器或伪正文，不在列表保留一个误导性的当前选中笔记。
- `draft` 可尚无 note ID，也可含未保存内容；不得用 `note == null` 直接等价于空白页。首次保存成功后成为 `note`。
- 空白页不持久化为 Markdown，不提供正文输入焦点；左侧列表、导航、设置和全局搜索照常可用。
- 页面只含简洁的“新建笔记 Ctrl+N”“搜索笔记 Ctrl+Shift+F”“关闭窗口 Ctrl+W”操作及提示；关闭说明按托盘实际可用性显示。中英文、深浅主题和键盘访问均须支持。
- 新建仍服从空间只读、安装中等既有保护；空白页不得绕过保护创建笔记。不能创建时按钮禁用并给出可理解的原因。

### 2.2 进入规则（维护者已确认）

| 触发 | 目标状态与前提 |
|---|---|
| 冷启动 | 完成既有状态初始化后进入 `welcome`，不自动打开上次笔记或创建草稿 |
| 从托盘/单实例唤起恢复已有进程 | 恢复隐藏前页面；已有笔记保持打开，原为空白页则仍为空白页 |
| 托盘“新建笔记”、Ctrl+N、页面新建按钮 | 先成功保存旧会话，再直接进入 `draft`；不先停在空白页 |
| 成功切换空间/普通列表与回收站分区 | 先成功保存旧会话，切换成功后进入 `welcome`；不自动选第一条或新建草稿 |
| 用户删除当前打开笔记成功 | 进入 `welcome`；批量删除只有当前笔记那一项成功才关闭它；其他条目删除不关闭当前文档 |
| 撤销普通删除 | 遵守严格代次撤销；恢复列表条目，不自动抢走当前空白页/新会话焦点 |
| 单 Markdown 导入成功 | 保留既有成功后打开导入笔记的流程；取消/失败不改变当前会话，过期回调不得抢占新空间 |
| 从列表/搜索打开结果 | 保存旧会话成功后打开对应笔记；搜索来源与删除状态按 §3 验证 |

失败的保存、切换或删除不能先清空旧缓冲。空间切换已在 core 成功、后续状态读取失败时，应明确进入可重试的状态恢复界面，保留必要的旧缓冲快照；不能把旧正文当作新空间可编辑内容。后台同步删除、冲突重定向或彻底删除通知仍遵守既有代次/救援保护，不强制卸载未提交输入。

### 2.3 Ctrl+W 与其他关闭入口

| 上下文 | Ctrl+W 的行为 |
|---|---|
| `draft` / `note` | 提交最终可提交输入、等待本地保存确认，成功后关闭编辑会话进入 `welcome` |
| 无可保存内容的新草稿 | 回 `welcome`，沿用既有空白草稿不建笔记规则 |
| 已存在但正文为空的笔记 | 按已有笔记保存规则处理，不删除该笔记 |
| `welcome` | 调用既有 `request_hide` / lifecycle；有托盘隐藏，无托盘退出；保存失败不关闭 |
| 保存失败或代次冲突待处理 | 保持原会话、正文与错误/救援出口，不切空白页、不隐藏窗口 |
| IME 组合中、模态框中 | 忽略导航快捷键，不确认候选、不穿透模态框 |
| 过渡中、按键自动重复、更新安装锁定中 | 不重复执行，不穿过保护；单次长按不能连续完成“关笔记＋隐藏窗口” |

修饰键、`defaultPrevented`、IME 与模态守卫延续现有顺序。两次操作应是两次独立按下，过渡期间后续关闭请求不能排队变成隐藏动作。

标题栏 X、Alt+F4、任务栏关闭、托盘退出继续原窗口级安全 lifecycle，不先经过空白页；Linux 隐藏/无托盘降级规则不变。不新增前端窗口关闭权限，不直接调用 hide/exit 绕过保存和更新屏障。

Ctrl+F 保持笔记内查找；空白页无动作，不改成全局搜索。Ctrl+Shift+F 从空白页也可打开全局搜索。Ctrl+S 在空白页不创建笔记。查找面板、编辑器 API、旧选中项与焦点须随会话正确清理。

## 3. 固定范围的本地全局搜索

### 3.1 空间与回收站

两端移除范围 chips/buttons 及“包含回收站”开关，不提供隐藏的过滤入口。每次查询固定为：

**所有 `kind=local` 本机空间 ＋ 当前选中空间在 `kind=account` 时的该一个账号空间；普通与普通删除笔记同时参加。**

| 当前选中空间 | 参与查询 | 不参与 |
|---|---|---|
| 账号 A | 本机空间＋A，各含普通回收站 | 账号 B/C、恢复归档、未在本机的云端内容 |
| 本机空间 | 本机空间，含普通回收站 | 所有账号；不记忆或带入“上次登录账号” |
| 恢复空间 | 本机空间，含普通回收站 | 当前恢复归档与其他所有账号 |

账号范围依据一次 registry 快照中的 selected profile，不依据“最近账号”“已登录账号集合”或后台同步账号。当前账号凭据过期不妨碍读取已有本地副本，不触发重新登录；登出使选中空间回本机后，原账号不再参与。账号能否通过既有入口重新选中沿用现有规则，不为搜索增加账号入口。

搜索与当前列表分区无关，普通列表和回收站中发起均执行同一固定集合。恢复空间继续排除；彻底删除完成的正文继续排除，pending/rejected 等边界服从原彻底删除契约。账号 A 结果跳转到本机后，下次查询按新的本机上下文，只搜本机；不保留一个隐藏的账号 A 搜索锚点。

常驻提示明确“仅搜索本机内容，含当前账号本地副本与回收站”；没有当前账号时显示本机与回收站口径。不新增云端搜索 API、不为搜索自动同步、切账号或导入笔记。

### 3.2 匹配、结果与失败

- 延续字面子串、ASCII 大小写不敏感、其余 Unicode 原字符匹配；支持 1 字符和标点，空查询不返回全量笔记，显示“输入关键词搜索”。不解释为正则/布尔/FTS 表达式。
- 沿用全量召回打分、合并排序后 top 50；超过时 `truncated=true`，明确提示前 50 条并建议细化关键词，不提供分页。排序保持相关性、更新时间、note ID，最后以 profile ID 消除跨库完全平局。
- 每条显示标题/命中摘要、命中数、时间、来源；来源与“回收站”是独立信息，同时可见。账号来源能标识账号及服务器，不能只写泛称“账号空间”。同一笔记 ID 在不同空间是不同结果，key 必须包含 profile ID。
- 账号来源使用请求时安全的 ProfileInfo 快照生成，不展示 token、设备凭据、数据库路径或 URL 中的认证信息。长标签允许换行/省略，完整来源仍可访问。
- 查询为后台本地操作，不使用全页面 busy 冻结编辑或导航。快速输入、关闭面板、切空间后，过期结果不能覆盖新状态。
- 本版保持整次查询成功/失败语义，不新增部分成功响应。任何目标库失败时显示可重试错误，不能伪报“无结果”或保留旧结果冒充本次成功。取消显示不代表已经终止底层调用。

### 3.3 打开结果

先保存当前编辑会话，再核对目标 profile、note ID、当前删除/彻底删除状态并读取最新笔记；失败保留可救援缓冲，不打开同 ID 的其他空间笔记。打开普通回收站结果时切到对应回收站上下文、保持只读与恢复规则；不得自动恢复或复制。定位当前笔记内的查询首个命中；若打开时正文已变为无命中，仍显示最新正文并如实提示，不使用过期摘要覆盖正文。

### 3.4 桌面布局与 Android 回归

桌面结果条目不能因纵向容器高度限制而收缩到内容溢出；容器负责滚动。标题最多一行、摘要最多两行并可省略，来源/删除状态/计数/时间按可用宽度换行，条目高度随内容自然增长。用户上下键移动选择时，选中结果滚动到可见区；鼠标滚动正常，不依赖修改结果上限修复布局。

Android 延续原生 LazyColumn，移除过滤控件后核对展开高度、键盘和滚动；来源行允许适应长账号和大字，使用 `(profile_id,note_id)` 复合 key。桌面 CSS 验证不代表 Android 已验收。

## 4. Android 基础列表回车续写

### 4.1 本版最小行为

只在可编辑源码、无 composing、选区折叠、光标处于明确识别的列表项逻辑行末时处理单次真实回车。软键盘与硬件键盘均适用，预览/只读状态不产生修改。

| 输入上下文 | 目标行为 |
|---|---|
| 非空 `- item` / `+ item` / `* item` | 插入一个换行及同种符号＋一个空格；保留识别出的当前项缩进 |
| 非空 `1. item`、`9. item` | 新行分别为 `2. `、`10. `；只生成下一项，不重编号原有后续列表 |
| 空标记行，如 `- `、`2. ` | 移除该行列表前缀，光标留在普通空行，退出自动续写；不产生重复空项 |
| 普通段落、转义标记、围栏/缩进代码、主题分隔线、语法不能可靠判定 | 原生普通换行，不猜测并改写正文 |
| 光标在行中、存在非空选区 | 原生换行/替换，不进行本版的列表自动续写 |
| 粘贴、加载、远端刷新、撤销/重做 | 不触发续写，不批量重写文本 |

基础编号为 CommonMark 合法的 1～9 位十进制数字＋`.`＋空白；无序符号为 `- + *` 后接空白。常见空格缩进在能确认列表上下文时原样沿用，不能把顶层四空格代码当列表。编号生成会超出合法位数，或缩进/上下文无法确认时，回退普通换行。

本版不新增任务列表、引用内列表、`)` 编号、多行项复杂续接、Tab 混合缩进的自动识别或嵌套层级升降；复杂输入按原生换行处理并保持精确正文。可明确识别的嵌套普通项只沿用已有缩进，不增加层级操作。任务项 `- [ ]`/`- [x]` 不作为普通列表项误续写。

这些是 Android 本版的明确最小规则，不要求复制 CodeMirror 的自动重编号或紧凑/松散列表转换；桌面 Markdown 扩展本版保持原行为。

### 4.2 输入与保存保护

一次用户回车最多应用一次命令。输入法候选确认不得追加换行/符号；软键盘提交 `\n`、硬件 Enter 和编辑器回调必须去重。批量编辑和 TextWatcher 不得递归执行续写或提交中间缺前缀的正文。

换行、前缀、删除空标记与光标更新形成单一可撤销的逻辑编辑：一次撤销恢复回车前文本与光标，重做恢复结果；不清空原生撤销栈，不替换全文来实现局部插入。新增前缀与正文一起进入既有保存缓冲，沿用 300ms 防抖/最长约 1 秒及必要 flush；不把高亮或命令计算完成当作保存确认。

不能阻断中文/emoji/选区/组合 span；对大文本不在每次 TextWatcher 中全量分析。延迟计算须核对笔记、空间、正文版本、选区和 composing；过期结果不能写回新文本。默认复用现有依赖，新增依赖必须先补 ADR/许可说明。
