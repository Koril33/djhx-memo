# v1 同步协议

版本：0.1.0，尚未发布。本文替代旧草案中互相矛盾的冲突描述。所有行为需通过 [一致性场景](conformance/scenarios.md) 验证。

## 1. 不变量

1. 本地操作先持久化，再发送；UI 不依赖联网完成保存。
2. 仅依据服务端 rev 校验并发，不用客户端时间或 ID 排序判断新旧。
3. 原笔记版本不匹配时保留权威当前状态，传入内容保存为独立冲突副本。
4. 推送幂等结果、笔记、变化日志和 seq 在同一事务提交；通知在事务提交后发出。
5. 拉取变化应用、shadow、保护中的本地修改和 cursor 在同一个本地事务提交。
6. 服务端 epoch 不匹配时禁止执行推送；客户端保全旧数据后恢复。
7. 墓碑、变化日志和幂等记录在 v1 不裁剪，避免长期离线设备失去必要历史。

## 2. 一轮同步

触发时先 flush 当前编辑；已提交操作可同步，未提交输入不显示已保存。协调器合并前后台触发，并按以下顺序工作：

1. 认证后调用 sync/status，核对服务器账号、epoch 与协议版本。
2. 将已有远端变化拉取到本轮 until；保留本地待发送或更新代次，不用远端正文覆盖它们。
3. 逐条冻结可发送的本地操作并 push；同一笔记按依赖顺序发送，每个请求最多 50 项且编码后 ≤8MiB。
4. 应用响应确认，处理冲突及更高本地代次，再次拉取到新的 until。只在无待发内容、当前拉取完成时更新“已同步”。

新本地编辑可在本轮结束后触发下一轮。超时、断网、5xx 和限流进行指数退避（1、2、4、8 秒，最高 60 秒，并加入抖动）；网络恢复和手动重试可提前触发。认证、协议/epoch 不匹配及永久字段错误不无限重试。SSE 只发更新信号；前台每 30 秒兜底检查，见 [API](api.md)。

## 3. Push 请求与事务

请求包含 `epoch` 与有序 `ops`。每项固定字段为 `op_id, note_id, base_rev, content, deleted`。op_id 由客户端生成，冻结后正文、删除标记和基准版本均不可变。

外层 JSON、版本和 epoch 先校验；外层失败时不执行任何项。合格外层中的各项按数组顺序、每项一个事务处理，允许逐项成功。响应保持相同顺序，每个 op_id 有一条结果。进程中断可能只提交前缀；客户端重试整个请求，由幂等记录恢复结果。

每项事务先查当前账号下 processed_ops：

- 同 op_id、相同规范化字段：返回原结果，不新增副本、版本、序号或通知。
- 同 op_id、不同字段：返回 `OP_ID_REUSED`，不得执行。字段指纹基于解析后的五个字段，不能依赖 JSON 空白和键顺序。
- 字段验证失败：返回逐项 error，不写实体。已存的幂等结果优先于其后实体状态变化。
- 新操作按下表裁决，并把成功结果和数据同事务写入。无副作用错误无需持久化，但同内容重试仍必须无副作用。

| 当前状态 | base_rev 与操作 | 结果 |
|---|---|---|
| 不存在 | base_rev=0 | 创建普通笔记，rev=1；可创建墓碑，以覆盖创建已发送但本地随后删除的恢复情况 |
| 不存在 | base_rev>0 | NOTE_NOT_FOUND，不把丢失的基准当成新建 |
| 已存在 | base_rev 大于当前 rev | INVALID_BASE_REV，不执行 |
| 已存在 | base_rev 等于当前 rev | 接受内容和 deleted，rev+1、分配账号下一个 seq，追加完整快照 |
| 已是墓碑 | base_rev 小于当前 rev，且 deleted=true、content 与当前完全相同 | already_deleted，不产生新版本；返回当前 rev/seq |
| 已存在 | 其余 base_rev 小于当前 rev（含 0） | conflict：原笔记不变，以新 UUID 创建 active 副本，rev=1，保留传入正文与来源元数据 |

冲突 reason：传入 deleted=true 为 stale_delete；否则原笔记已删除为 edit_after_delete；其他为 stale_edit。冲突副本始终 deleted=false，保证离线内容可见。普通删除保留正文。不存在的普通新建 ID 碰撞依同样版本规则处理，不覆盖既有内容。

accepted / already_deleted 响应带原 note_id、当前 rev/seq；conflict 响应带原 note_id、当前 rev，以及 conflict_note_id、conflict_rev 和 conflict_seq。响应不携带完整正文，权威快照从 Pull 获取。error 项带稳定 code 和 retryable。

## 4. 客户端确认与继续编辑

冻结代次为 G，发送期间最新可见代次为 H：

- accepted 且 H=G：以发送快照和返回版本更新 shadow，完成该操作。
- accepted 且 H>G：只确认 G，保留 H；下一操作基于已接受的新 rev 发送 H，不能清除 H 的待发送状态。
- conflict：发送快照已由服务端保存在副本。原笔记回到权威状态；若 H>G，将该笔记的后续本地内容及焦点迁移到冲突副本 ID，以 conflict_rev 为基准继续编辑/推送。不把后续内容套回原笔记。
- already_deleted：确认已知删除；若存在 H>G 的恢复/编辑，仍以返回版本发出后续操作。
- 可重试 error 或响应丢失：冻结记录保留，原 op_id 重试；永久 error 阻止该笔记的自动重试，保留内容并提示处理，不阻塞其他笔记。

处理确认、shadow、可见笔记、冲突映射和 outbox 是一个本地事务；提交前崩溃则重放响应/请求，结果不重复。收到 Pull 先观察到自己已提交的操作时，不自动删除冻结操作；仍通过幂等重试取得正式结果。可见后续编辑使用当时的已知基准，不因拉取而自动提高 base_rev，避免把真正冲突改写成无冲突覆盖。

## 5. Pull 分页与并发

GET sync/pull 提交 epoch、cursor，可选 until、limit。首个页面未传 until 时，服务端读取该用户 head_seq 为 H，返回 until=H；客户端在后续页固定此值。

- 查询不可变 changes：`cursor < seq <= H`，严格按 seq 升序。
- 默认最多 50 项，最多 100 项；序列化响应最多 8MiB，达到数量或字节限制则分页。单个最大正文在转义后也必须能够独立返回。
- next_cursor 为本页最后一个已返回 seq；空页时保持原 cursor。has_more 表示 (next_cursor,H] 是否仍有变化。
- 服务端只分配实际变化序号，账号内无未提交的占位空洞；当 has_more=false 时，next_cursor=H。
- 第一页后的并发编辑获得更大 seq，留到下一轮；当前轮的旧快照不被替换或删除，所以分页不会跳过变化。
- cursor 或 until 大于服务端 head、until<cursor 或不符合类型时返回 CURSOR_INVALID，不静默跳到最新位置。

客户端逐条 reducer 应用快照：shadow 只前进，不倒退；无待发送/本地新代次的笔记可更新可见内容，有本地内容则保留其不可变基准及草稿。已通过 Push 知道更高版本时，可跳过较旧实体快照，仍按顺序推进 cursor。本页应用失败则整个本地事务回滚，cursor 不变。

首次全量同步也是 cursor=0 的同一流程，遍历到 H；可以在加载中继续本地编辑，但不得宣称已同步，也不得覆盖编辑缓冲区。

## 6. Epoch 与备份恢复

sync_epoch 是服务器部署的随机恢复代次，保存在不随 SQLite 备份回滚的运行元数据中。正常重启不变；恢复任意旧数据库前，管理员必须停服并生成新 epoch，再对外开放。所有认证成功响应、sync/status、Push/Pull 与 SSE 信号都带 epoch；Push/Pull 必须携带客户端预期 epoch。

不匹配时返回 SYNC_EPOCH_MISMATCH，Push 不执行。客户端停止自动推送，保全旧数据库为“恢复空间”，可查看和导出；新建账号副本从零拉取。界面解释恢复原因并允许选择旧内容，复制为新 ID 的恢复笔记，不重放旧 op_id，不静默覆盖新权威数据。若恢复同时使 token 失效，先重新登录，再进行上述核对。

epoch 校验及 Push 执行必须针对同一运行实例；恢复期间完全停止旧进程，不能在仍接受写入时切换数据库。epoch 丢失也必须视为恢复并轮换，不能猜测旧值。此机制不能自动找回未进入备份、且所有客户端也已丢失的内容。

## 7. 删除、恢复与注销

删除/恢复与正常写入共用版本和幂等规则。未发送过的离线新建删除仅留本地回收站；其他删除进入 outbox。墓碑正文在本地和服务端保留，物理清理另行立约。

注销、吊销、切换空间不删除 outbox。未经确认不将待同步内容复制到其他账号。后台任务在空间切换后不得把原账号任务绑定到新账号凭据；每个任务固定 profile_id/user_id，执行前复核。

## 8. 协议演进

API 路径版本为 /v1，sync/status 返回 protocol_version=1；客户端发现不支持版本时停止同步并提示升级，本地功能继续可用。v1 可增加向后兼容的可选字段；改变冲突、删除、幂等或分页语义需新版本及迁移方案。
