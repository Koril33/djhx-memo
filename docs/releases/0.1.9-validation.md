# Android 0.1.9单端发布与验证

日期：2026-11-14。维护者确认PR #21已合并，并授权单独发布Android0.1.9/code10；Windows/Linux继续0.1.8。本记录初始为发行准备，完成项与待验收项分别追加，不以有附件代替真实安装。

## 来源与范围

Gitea合并提交`6b26838`保留修复提交`1cd9228`及交付记录`bef62fb`。行为见[安装兼容规范](../../spec/android-install-compatibility.md)，独立平台评审见[评审记录](../reviews/android-install-compatibility-review.md)。本次发行准备只修改文档与官网分平台下载清单，Android生产源码保持该已评审合并版本；core0.1.7、server0.1.4、协议2/schema3不变，无服务端/笔记迁移。

修复保留完整系统确认Intent与固定错误分类，并增加显式“通过系统安装器安装”兼容入口。两条入口均执行原目录/原证书/包身份校验及保存屏障；旧回调隔离、清理与core恢复失败可重试。没有取消未知来源授权或系统用户确认。

## 已完成的修复检查

前轮相同Android生产源码完成detekt、13项JVM测试、debug/release Lint和构建；API35 x86_64隔离instrumentation共56项，52通过/4条件跳过/0失败，含真实系统确认页打开与取消后原ID中文emoji笔记保留。双ABI JNI按锁文件生成，原证书、16KiB zipalign和无嵌套fixture已核对。完整命令、跳过原因、候选哈希见[修复验证](../android-install-compatibility-validation.md)，本轮从最终发行提交重新构建与分发结果待下文补齐。

## 发布安排

仅生成`djhx-memo-0.1.9-android.apk`及SHA256SUMS，GitHub v0.1.9不重复附Windows/Linux旧包。官网Android直达本版APK，另两端仍直达v0.1.8的EXE/DEB。签名目录增加序号，保留Windows0.1.8条目的来源提交、URL、哈希和包签名，不把它改写为0.1.9。

## 已知限制与恢复

Civi（Android13/HyperOS1.0.2.0.TKVCNXM）的旧0.1.7应用内升级0.1.8未弹系统确认，浏览器同证书覆盖成功、原笔记正常；尚未取得该机系统失败码，不能断言唯一根因。新0.1.9流程在该真机、其他OEM/API/arm64及完整设备矩阵仍待验收。发布授权不等于这些项目已通过。

0.1.8升级到0.1.9的安装由旧进程执行，修复不能追溯生效；失败时使用官网正式APK浏览器覆盖一次，不卸载或清数据。要验证新安装逻辑的完整升级闭环，需要由安装了0.1.9修复代码的客户端再向更高版本升级。Windows/Linux本轮不重编或重发。
