## 故障与修复

维护者日志中的`lost connection`发生在SCP上传APK时，尚未进入sudo推广。这属于传输连接中断；服务器现场的Go/SSH服务没有重启，现网仍为官网0.2.1、current12。现有证据不能进一步断言是哪一段网络设备主动断开，也不能把这次中断归因于安装包签名或目录验证失败。

本机部署工具增加SSH/SCP连接超时和保活，创建私有暂存、上传及远端哈希核对最多尝试3次；重传写入同一私有暂存，通过完整验证前不切站点。主机密钥保持严格验证。正式sudo推广只执行一次，避免网络回执丢失后重放已被客户端接受的目录序号；没有更改工作流、已发布tag、安装包、签名或应用身份。

本轮首次实际下载在未继承交互终端代理的子进程中停留于GitHub下载阶段。只停止该任务的下载子进程，确认尚未上传，再让本次部署子进程使用本机既有HTTPS代理，未修改全局网络设置。随后发布包下载、镜像校验、Rust目录/资产验签、整包上传及远端推广均成功，上传阶段没有触发重试。

远端成功报告`deployed ...; catalog 13`后，本机命令在`clean remote staging`阶段退出1：sudo运行的发布器导入Python工具，在上传者0700目录内留下root所有的`__pycache__`，普通账号无法删除。这次退出不代表推广失败。本轮先核对实际current13及线上站点，再只删除该次已确认路径内的缓存和空目录；未重复推广或回退current。`deploy-remote-v2.sh`现设置`PYTHONDONTWRITEBYTECODE=1`，防止后续再产生这类root缓存；在生产Linux的独立私有探针中以sudo执行真实导入，再由普通上传账号清理通过，探针已移除。
