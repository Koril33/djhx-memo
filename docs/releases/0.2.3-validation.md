## 3 2026-11-24 设置交互修正

维护者报告切到长设备列表时弹窗变高、点击info后Windows显示STATUS_BREAKPOINT。前者可由仅设min-height的布局直接解释；后者是渲染进程崩溃，尚无崩溃栈，不能仅凭错误码认定根因。

- 修正：有界正文高度、保留正文内滚动且标题/tab不收缩；切页关闭说明并复位scrollTop。说明组件移出label/h3，不再让展开区域参与勾选框标签布局；保留原说明全文，使用36px图标区域、aria-expanded/controls/describedby及独立ID关联。焦点陷阱纳入summary。
- 新增`desktop/scripts/check-settings-browser.mjs`：以现有Vite编译真实App/Help，Tauri IPC完全替换为合成账号/18条设备，不连接真实服务、读真实账号或使用用户浏览器资料。Windows headless Edge在800×560与1280×900两组下通过：六tab反复切换高度一致、长列表内部滚动、滚动复位、反复20次info/Esc、焦点返回、点击info不改变勾选值、关联ID/36px区域以及本机设备页Tab焦点循环。该浏览器结果不替代原生WebView2/GTK或读屏验收。
- 修正后Svelte检查0错误/0警告、ESLint、55项既有单元测试和生产构建通过；新增浏览器回归独立列出，不将其混入55项数量。生产构建保留既有大chunk提示，没有关闭告警。
- Windows原生WebView2的STATUS_BREAKPOINT复现/消失尚未验证，不能写成已确认根因或已证明彻底消除崩溃；Linux GTK、Android菜单及完整真机矩阵仍待验收。本轮不发行、不部署、不改core/server/schema/协议或运行时依赖。
