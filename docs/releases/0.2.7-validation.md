## 4. 交叉评审状态

`batch_purge` 删除语义与桌面设备页鉴权并发已由独立 Claude 子代理交叉评审，**首轮未通过**，发现并已修复以下缺陷后复评：

- **A（删除语义）**：core 语义（幂等顺序、事务隔离、精简回执、原 ID 不复活）通过。修复两项：
  - D-A1 结果口径：回执无法区分「新入队 pending」与「本就 pending 的幂等空操作」，原「已请求 N」对已 pending 条目过度声称。改为「已彻底删除 X · 待同步 Y」（Y 为结果 pending 数，含本就 pending 者），并同步修订 spec §2/§2.1 与 `permanent-deletion.md` §2。
  - D-A2 失败静默：批量彻底删除的失败项原先不计数、不保留选中。现保留失败项选中并提示「失败 Z 条」，两端同改。
- **B（设备页鉴权并发）**：修复阻塞缺陷 B1——`revoke` 成功路径中 `void loadDevices()` 会先推进 `devicesSession`，导致 `finally` 的会话序号 gate 恒假、`revoking` 永不复位，**一次成功后同会话内无法再吊销任何设备**。改为按「当前活动吊销 id」（`clearRevoking`）复位，并新增 `devices.test.ts` 覆盖 `receiptIsCurrent` 与 `clearRevoking`。另修 B2（成功刷新清 `revokeError`）、冷启动失败时「刷新失败」与「暂无设备」同时显示的矛盾（并保留行内重试入口）、并为重复刷新加在途合并（吊销后强制刷新），同步更新 spec §5。**已知测试缺口**：`devices.test.ts` 为纯函数级，`App.svelte` 的 `revoke` 行为级回归（成功后能再次吊销）受现有组件测试基建限制未覆盖，列为后续项。
