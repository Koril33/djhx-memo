## 安装与真实窗口

`dpkg -i` 从 0.1.2 覆盖到 0.1.3，退出码 0；实际安装的二进制与 deb 载荷 SHA256 一致。测试前没有正在运行的 Memo 进程，先前记录的 PID 也已不存在；未停止任何用户编辑进程。原用户数据目录和配置中的 10 个既有文件在测试前后逐字节哈希一致。

独立本机空间使用一条中文/English/emoji 合成笔记，包含 Python、TypeScript、PowerShell 与 unknown-language 代码围栏：

- 源码和预览均显示语言标记对应的高亮。AT-SPI 实际文本属性中，关键字、名称、数字和字符串为四种不同前景色，两视图对相同 token 的颜色一致；未知语言代码保持普通正文色。
- Python 字符串中的 `<script>alert(1)</script>`、TypeScript 字符串中的 `<img src=x onerror=alert(2)>` 显示为代码文字。前端测试同时验证着色片段与间隙均转义，没有生成 script/img 节点；外部图片、危险协议及原始 HTML 的既有限制测试继续通过。
- 已实拍英文浅色源码/预览、英文深色预览、中文深色源码/预览、中文浅色源码/预览；观察到的代码颜色在两套主题下均清晰，语言切换未改写笔记内容。源码/预览切换正常。
- 此独立 X11 会话没有托盘宿主，应用明确显示关闭后保存并退出。两次发送原生窗口关闭事件均正常退出（退出码 0）；重开后中文与浅色偏好保持，重新选择合成笔记，SQLite 中正文与原始 fixture 完全相同。

初期辅助脚本遇到 DBus 激活环境不完整导致启动等待，以及 WebKit AT-SPI 的缓存 SHOWING 状态和编辑区末尾附加展示换行；均通过正确传递隔离环境、直接查看真实截图并以数据库原文验证持久化来区分，没有为此修改客户端代码。最终辅助脚本退出码 0。未用隐藏编辑器的缓存状态作为模式切换通过证据。

本机忽略目录 `.local/releases/0.1.3/linux/` 保留构建日志、AT-SPI/原生输入辅助源码、逐 token 颜色记录、合成笔记校验摘要及截图，包括 `en-light-source.png`、`en-light-preview.png`、`en-dark-preview.png`、`zh-dark-source.png`、`zh-light-preview.png`、`restart-zh-light-source.png`。这些仅为本轮演示内容，不作为公开安装包附件。
