# ADR 0022 个人服务器作为主要下载源

- 日期：2026-11-22；状态：**产品下载源已确认，以下传输及部署设计待实施评审**。
- 延伸：[ADR 0016](0016-automatic-updates.md)、[ADR 0019](0019-update-catalog-website-ci.md)；行为以[0.2.2 规范](../../spec/client-0.2.2.md)为准。

## 选择

主要下载源为固定 HTTPS 域名 `memo.djhx.site`，GitHub 为可选备用源。客户端只选择安装包传输路径，目录签名、撤回、包身份与安装屏障保持统一。GitHub Actions 继续负责构建及签名；维护者本机部署，生产服务器写权限不进入 CI。

**保留 v1 签名目录的 GitHub 规范 URL，以受信本地规则推导个人源 URL。** 目录先验签并验证本仓库、tag、标准文件名与目标，再按 `https://memo.djhx.site/downloads/releases/<tag>/<asset>` 发起下载。两个来源必须满足同一签名资产的字节数、SHA256 和平台签名；来源不能改变资产身份。

这种方式不需要给严格拒绝未知字段的旧目录增加 mirrors 字段，不需要新的 feed，也不把个人服务器实时代理到 GitHub。旧客户端继续使用 GitHub，升级到 0.2.2 后才能选择新源。GitHub 备用不承担官网签名目录全站灾备；新客户端的版本检查仍需要官网。

## 约束

- 推导是客户端中明确审核的信任授权，不能笼统宣称个人 URL 本身出现在旧签名 payload 中。签名绑定资产身份；固定主机与路径规则限定传输位置，两者共同保证边界。
- 个人源拒绝 HTTP、非标准端口、userinfo、query、fragment、路径穿越及重定向；GitHub 保留其必需、受限的资产域名重定向。禁止任意 URL 字符串替换。
- 来源偏好与防回放状态分开保存，不更改原 `state.json` 的 sequence/digest；损坏来源偏好可回退默认，损坏安全状态仍阻止更新。
- 首版手动选择与手动切源重试，不隐式回退。完整缓存以版本/目标/哈希识别，半包不跨源续传。
- Linux 只提供浏览器下载入口，使用个人源 latest 跳转及 GitHub 每版固定名 DEB 别名；不加入当前自动安装 targets，不改变 v1 兼容字段。
- 服务器静态文件区与官网轮换目录独立，发布只接受已验证的 CI 文件；不在服务器重新打包或重新签署 APK。
- 同源的下载流量可能竞争同步带宽。下载路径单独设置并发、速率与磁盘预算，验收时确认 SSE/API 不受下载任务拖累。

## 备选与代价

拒绝直接把现有目录 URL 改为个人源：旧客户端会拒绝。暂不增加 v2 多镜像目录：仅有两个固定来源时会增加旧版过渡和防回放迁移复杂度。将来需要任意镜像、独立灾备 feed 或跨 schema 更新时，再设计版本化签名格式与迁移。

代价是公开资产持久存储、同包校验、最新 DEB 别名和客户端传输选择逻辑；不新增运行依赖或 Linux 安装助手。发布前必须通过主源、备用源、旧客户端升级、故障取消及防回放用例，不能以 HTTPS 可访问代替验签。
