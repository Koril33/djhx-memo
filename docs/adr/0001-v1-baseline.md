# ADR-0001：v1 范围与可靠性基线

- 状态：已接受方案；尚未实现，协议和高风险实现仍需交叉评审
- 日期：2026-11-03
- 决策依据：项目负责人确认三端、托盘、未登录使用、注册登录、日常可用与暂缓 CI；其余采用本次评估建议

## 背景

v0.1 草案已有技术方向，但冲突策略有矛盾，未定义本机空间、可靠重试和恢复行为。首版应覆盖负责人实际跨端记录需求，以尽早形成可日常使用的闭环。当前自建 Git 无 CI/Runner。

## 决策

| 事项 | 已选方案 | 原因与影响 |
|---|---|---|
| 平台 | Windows、Android、Linux 均为 v1，Web/Apple 暂缓 | 三端一起验收，不提前承担浏览器持久化与 Apple 构建成本 |
| 桌面 | Tauri 2，Svelte/TypeScript/Vite，CodeMirror 6；前端放 desktop | 沿用 Rust 核心，编辑器采用成熟方案；暂不为未来 Web 建共享包 |
| Android | Kotlin/Compose + UniFFI | 保留原生输入与生命周期，复用核心同步逻辑 |
| 本地数据 | Rust + rusqlite，随包 SQLite，独立空间数据库 | 统一 SQLite/FTS 能力，减少系统版本差异；需跨端验证 |
| 未登录 | 独立本机空间，登录后可选复制导入 | 不未经选择上传，也不把本机笔记绑定到错误账号 |
| 注册 | 一次性邀请码 + 用户名密码，注册后签发设备凭据 | 满足朋友使用，避免公开注册；无需邮件系统 |
| 认证 | Argon2id 密码，不透明可吊销设备 token，90 天有效 | 单实例个人场景易管理，不引入 JWT/刷新令牌体系 |
| 冲突 | 保留服务端当前版本，传入内容生成可见副本 | 长期离线设备不会静默替换现有权威正文 |
| 删除 | 回收站、墓碑保留，不自动永久清理 | 可恢复，避免旧设备复活数据；存储增长需观察 |
| 同步 | 不可变 outbox、按账号 seq 的完整变化日志、固定上界分页 | 重试、并发和崩溃可精确验证；v1 用存储换简单可靠性 |
| 实时通知 | SSE 信号 + 前台 30 秒兜底拉取 | 单向更新信号足够；原生客户端可设置 Authorization 请求头 |
| 后台 | Android WorkManager 尽力同步，回前台立即补拉 | 不对系统后台调度作五秒承诺 |
| 搜索 | 字面子串语义，trigram 加速，短词兜底 | 支持中文两字和单字，不把 FTS 查询语法暴露给普通用户 |
| 托盘 | Windows/Linux 必需；菜单可打开、新建、同步、退出 | Linux 不依赖左键图标事件；托盘失败不隐藏窗口 |
| 备份 | 日一致快照、加密异地备份与恢复演练 | 首版目标 RPO 24h、RTO 2h；Litestream 后置 |
| 恢复 | 独立 epoch 轮换，保全旧本地库，选中内容以新 ID 导入 | 防止旧 cursor/outbox 作用于恢复后的新历史 |
| 质量 | 开发机自动检查、跨端验证、交叉评审和 7 天自用 | 不依赖尚不存在的 CI/Runner |

## 备选方案

- 最后上传者覆盖原笔记：旧设备重连会改变当前正文，v1 不采用；内容副本仍须保存。
- CRDT：当前不做多人协作，先采用整条笔记冲突副本。
- 未登录笔记登录后自动上传：可能误传到错误账号，改为明确选择复制。
- Web 与桌面先共享包、Rust WASM：独立 Web 已暂缓，避免提前建设。
- WebSocket：双向通道暂不必要，改用单向 SSE 通知并通过 HTTP 同步。
- 自动清理墓碑/日志/幂等记录：会影响长期离线与恢复协议，另行评估。
- 先搭 CI/Runner：当前无基础设施，先建立可重复的本地检查，不降低质量要求。
- “任何故障绝不丢数据”：无法覆盖未提交输入与所有副本同时损坏，改用可验证持久性及明确 RPO。

## 依赖引入与许可证

本 ADR 接受上述技术路线，不声称已安装、锁定或完成所有依赖审查。实施 PR 必须列出直接依赖的确切包名/版本、许可证、官方维护来源、使用理由，并提交锁文件。新增未涵盖框架需要新 ADR；Go SQLite 驱动、Android Markdown 渲染器、凭据库适配等具体库在 M0 验证后补充依赖决策记录。

优先采用原项目官方维护的稳定版本，禁止只依据 AI 熟悉程度改变框架。标准库能完成的 UUID/随机数/HTTP 等工作不为方便随意增加框架；不同语言所需实现库仍需核查。

## 影响

新增回收站、本机导入和恢复空间的界面/测试成本，以换取明确的数据保全路径。完整变化日志与不清理策略适用于个人小规模，发布后观察体积，再设计压缩与清理。三端安装、Linux 输入法/托盘和 Android 绑定必须早期验证。

方案选择已经明确，实施者无需再次要求负责人逐项决策；若验证发现与范围不兼容的事实，记录证据和替代方案再调整规范。
