## 3. 技术路线

### W1：先改善实际源码页，随后改善预览

1. 在现有 SourceEditor 标记 setText、正则、span 清理/添加、update、测量/布局耗时；单独观测首次打开与每次输入。原 20,000 行样本未开预览却停顿约 135.6 秒，源码页必须独立验证。
2. 使用 UTF-8 字节阈值和装饰数量预算，阻止大笔记反复运行四组全文正则。**候选阈值 128 KiB**与当前 core 共享代码高亮的上限一致，但 Android 本地 Markdown 正则是独立路径，不能假定已经受到这个上限保护。对小文本合并/防抖展示更新；保存按原节奏执行。
3. 后台计算仅处理不可变快照；主线程装饰应用须有预算并校验 profile/note/buffer version/theme。中文组合期间不破坏 span；原始可编辑缓冲始终是正文来源。
4. 后台解析预览到不可变块模型，按可见块组合；保留源码绝对行与任务映射。大段落/大代码块另做分段或降级，核对既有复制入口、滚动锚点、切回源码和无障碍；若分块影响已有文字选择，再覆盖跨块行为，不顺带新增复杂选择特性。
5. 若去掉高亮仍达不到交互目标，先优化原生布局/可见范围策略，再决定是否需要更大的编辑器改造。不能提前把“仅跳过高亮”当成已证明有效的最终修复。

0.1.13新增/现有路径也纳入测量：SourceFind全量匹配及逐命中span、关闭查找后的刷新成本；ListEnter复制正文/前缀及围栏扫描；EditText全文比较/setText和测量；预览组合路径内全块展开。核心128KiB代码高亮上限不覆盖这些路径。只允许降级自己拥有的装饰，不清空IME、选区或编辑历史。当前/可见查找高亮方案待Q2；桌面源码模式仍运行预览渲染，是否正式优化待Q1，不先宣称停顿已实测。

依据：[Android 响应性指南](https://developer.android.com/topic/performance/anrs/keep-your-app-responsive)与[Compose 惰性列表](https://developer.android.com/develop/ui/compose/lists)。惰性布局减少不可见项组合，但无法自动解决单个 item 内的巨大文本。项目当前 Compose foundation/UI 1.7.5，不采用最新文档里未锁定的新 API 来替代兼容性评估。

### W2：隔离页面请求状态，保留真实活动屏障

现有 Android 路径为：进入 Devices → loadDevices → 通用 action 设置全局 busy → 关闭/切 tab 禁用 → 失败 report → MainActivity 通用模态消息。CoreGateway 已在 Dispatchers.IO 调用，core HTTP 连接/总超时为 8/35 秒；这是交互状态耦合的证据，不是主线程网络 I/O 的证明。

推荐设备页状态模型：`loading + data + inlineError + request identity`，同账号有缓存时后台刷新；错误和重试仅作用于该区域。缓存首期只在内存，账号/会话隔离并随注销清除。离开页面立即作废回执，不等待请求超时后才能返回。

通用action/busy原本也在串行化操作，不能直接整体删除。读取携带profile锚点，并引入会话版本隔离同账号重登；保存、切空间、登录/注册和吊销等动作保留局部互斥。真实请求完成前保持in-flight计数，即使界面已离开；按profile/会话与总体并发限制重复刷新，不让逻辑取消无限积压原生请求。

真实取消与逻辑取消分别处理：本版可先做到页面不等待、旧结果不生效、请求数量有界；如进一步缩短/取消 HTTP，需独立请求级设计，不能全局取消同步或提前释放更新活动租约。安装屏障仍等待真实活动排空。

其他联网入口按职责检查，避免为消除等待而误报成功：

| 入口 | 0.2.0 需核查的行为 |
|---|---|
| 设备列表/刷新 | 区域加载/缓存/错误/重试；可离开；重复请求有界 |
| 吊销设备 | 操作局部等待、确认仍在；成功回执前不标成已吊销；晚到旧会话回执不影响新会话 |
| 登录/注册/重新登录 | 表单等待与错误就地展示；可取消表单，不假装成功；密码/邀请码按既有生命周期清除 |
| 注销 | 保留现有本地注销与远端吊销未完成的区别，不存旧明文 token，不因离线无限锁住页面 |
| 手动/后台同步 | 本地编辑继续可用，显示实际云状态；保存与冲突规则不改 |
| 更新检查/下载 | 页面进度和错误局部展示，取消/稍后保持可用；安装授权、系统确认、签名与真实操作屏障不削弱 |
| 纯本地搜索/编辑/导出 | 不额外依赖服务端或设备列表成功 |

桌面也核查相似 run/busy 路径，但 Android 是用户已报告平台；未执行故障注入前不把所有桌面入口记作已复现。

### W3：用视觉区分段落，正文完全不变

先做三组只读文本样例：一个超长源码行的折行、同一段内两行、空行分隔的两段；再加入列表、引用、标题、代码围栏及空行。用相同宽度/字体比较行距与段距，不依赖正文自动加空行。

“不改变Enter”以0.1.13为基线：普通段落沿用LF，列表继续自动续写/空项退出；查找定位、光标和一次撤销均须匹配新布局。优先行高与真实空行的轻量方案，额外语义段距只在确有视觉收益且满足W1预算时加入，不默认增加排版设置。

候选起点：桌面行高 1.70/1.75（当前 1.85）、Android 1.60（当前 1.65）。段落先利用真实空行形成留白，如仍不足，再比较约 0.3–0.5em 的语义段落附加间距，避免“空行高度 + 大 margin”双重膨胀。最终数字尚未选定。

CodeMirror 高度装饰与 Android paragraph/line-height span 都要正确参与布局和命中测试，不能逐次按键全量创建大量 span。大笔记是否简化额外排版装饰与 W1 一同测；实际空行/段落结构始终可见。[CommonMark 段落](https://spec.commonmark.org/0.31.2/#paragraphs)及软换行语义保持。

### W5：默认目录和兼容身份分离

NSIS 当前以 INSTALLIDENTITY“简记”构成默认目录和旧注册表识别键；名称显示已用 MemoBrandName。本版保持旧键，只新增可本地化的新装默认目录名，旧路径恢复在语言默认计算前生效。

新装目录选择或 `/D` 优先于语言默认值。升级先独立识别旧目录，不能只在INSTDIR为占位值时恢复旧位置；现有模板的显式/D和交互目录页都需校验。旧安装指定不同路径的提示/退出方式待Q4，不能静默新建第二套。`/UPDATE`、`/NS`、静默/被动与修复流程必须覆盖；安装语言使用NSIS已解析语言，不读应用内语言来搬目录。用户数据、凭据和公钥不搬动；签名与更新链延续。
