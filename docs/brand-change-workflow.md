# Logo与名称更新固定流程

本流程用于当前0.1.10及后续品牌调整。行为以[0.1.10规范](../spec/client-0.1.10.md)为准，视觉规则见[品牌规范](brand-guidelines.md)。个人构建机路径、签名材料和服务器连接只放仓库外或忽略目录。

1. **确认品牌输入。** 修改`assets/brand/profile.json`中的中文/英文显示名及图形配置；当前为阳墨随记 / DJHX MEMO、logo-pack-v1/sunrise。图形与显示名独立，保留原始包与其SHA256，不执行包内安装依赖/生成命令。新增素材版本使用新目录，不覆盖旧包。
2. **先归档再替换。** 旧图形的母版、每个平台受管文件、原哈希清单与生成器归档到`assets/brand/archive/`。新品牌资源通过统一生成入口写入，禁止各端手工另画。`paper-v1`是本次保留的绿色纸张旧版，可在配置中重新激活；旧名称也可从归档配置恢复。
3. **生成并检查。** 仓库根运行`python scripts/generate-brand-assets.py`，再运行同命令加`--check`。入口使用Python3.11+标准库消费已渲染资源，检查源包哈希、路径范围、PNG/ICO尺寸、Android XML和全部生成输出；不要求所有构建机安装图像渲染器。新素材/新几何应先完成设计导出，再接入映射。
4. **核对名称触点。** 应用页头、窗口/托盘提示、关于/更新页、文件对话框、Android启动器、Windows安装/卸载/快捷方式、Linux desktop条目、官网文字/页面标题/分享信息均读取同一品牌定义。系统入口按系统/安装语言，应用内按应用语言；不要在切语言时反复改系统快捷方式。
5. **保护安装身份。** 对照配置中的固定身份核对：app.djhx.memo、djhx-memo包名/二进制、Windows兼容INSTALLIDENTITY“简记”、旧安装目录和卸载键、Keystore/凭据服务/数据路径与更新公钥保持。禁止全局替换旧名字或通过换包标识刷新图标。快捷方式只迁移确认指向本应用的项目，不能覆盖其他目标。
6. **检查原生效果。** 检查16/24/32px、浅深任务栏、Linux面板、自适应遮罩和Android13主题图标。Windows系统任务栏主题独立于应用主题；未知Linux面板应有可见兜底。Android同时覆盖v26/v33资源。保留最小触控区域，截图使用合成内容。系统有缓存时先重启应用/启动器后复核，不修改安装身份。
7. **本地验证与提交。** 执行品牌`--check`、文档/源码安全检查和受影响模块的检查，记录三端实测/未测；提交配置、素材、派生资源、流程与规范。品牌归档不计入活动资源；清理旧活动输出仅限生成清单登记且哈希未被手工改动的文件。
8. **发布与复核。** 从已评审同一提交构建三端安装包，沿用签名钥并验证覆盖升级、原笔记与快捷方式。发布新版本资产而不覆盖旧标签/附件，匿名核对后更新官网清单、完整静态构建和签名目录。记录实际版本/哈希、部署回退位置、验收限制；只恢复旧图形时也作为新版本发布，不能降级更新目录。

恢复图形时，把配置的图形profile改为`paper-v1`，执行同一生成/检查流程；名称配置可以保持新名。恢复旧名称时显式填写归档记录中的显示名，仍保护内部身份。未来增加第三套品牌同样先创建版本化输入与映射，不覆盖paper-v1或logo-pack-v1。

Windows安装器辅助验证入口为`python desktop/scripts/check-brand-installer.py`，需要已配置的NSIS及Tauri的`utils.nsh`，路径可用参数指定。它编译生产模板中的真实快捷方式助手，在带所有权标记的独立目录和临时注册表键中验证自定义文件夹、目标冲突、大小写改名与搜索预算；不访问正式卸载键。已存在两个指向本应用的不同入口时，保留旧别名，仅记录新入口，避免删除用户自建入口。该组件测试不能代替正式覆盖安装和原生图标检查。
