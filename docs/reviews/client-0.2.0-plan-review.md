## 3. 矛盾、遗漏与注意点

### R1：版本、schema和编号口径过时

旧0.2.0文档仍写客户端/core0.1.10、local schema3、Android code11；现在基线分别为0.1.13、4、14。0.2.0不新增迁移时应保持local schema4；Android正式code须高于最终已发布最大值，按当前基线候选为15，不能把版本显示名0.2.0当作code自动递增。

core是否随客户端统一到0.2.0是工程版本策略，不是同步协议升级。CI当前tag检查只比desktop版本，不能替代Cargo/Android/锁文件的一致性检查。

### R2：“每次Enter只产生LF”必须限定上下文

旧排版文字容易被解释为所有Enter都只能插入LF，与0.1.13 Android列表自动插入前缀/空项退出冲突。应明确：普通段落保持既有LF语义；列表继续执行0.1.13命令；本版不通过改正文创造段距。

旧规范“保留Markdown语义”的方向不变。自动折行与段内单LF使用同类行距本来就符合已选语义；真正段落由实际空行/块边界区分，不应把每个逻辑行装饰成独立段落。

### R3：语法高亮、查找高亮和编辑命令不能混为一谈

[SourceEditor](../../android/app/src/main/java/app/djhx/memo/SourceEditor.kt)的 `SyntaxColor` 正则、共享代码着色、[SourceFindHost](../../android/app/src/main/java/app/djhx/memo/SourceFind.kt)的 `FindHighlight`、IME/选区和列表续写是不同职责。允许大笔记简化语法高亮，不自动授权关闭查找、假报命中数、破坏选区或取消列表命令。

当前查找在UI路径中重算匹配，并对全部命中设置span；高频单字可能产生大量装饰。建议保留完整计数和上一/下一处，只为当前/可见区域命中绘制高亮，但这涉及原“全部命中高亮”的展示承诺，需要Q2定稿并同步搜索/查找规范。未确认前不能静默缩减。

当前ListEnter会复制正文/前缀并扫描围栏上下文，属于回车时的独立开销；只跳过Markdown正则不会消除它。M2试验须包含大笔记中的列表回车、代码围栏及开启查找后连续编辑。

### R4：只关闭着色不一定解决大文本布局

Android原生EditText仍按完整正文高度测量，update存在全文字符串比较/必要setText；预览仍在组合路径解析并展开全部块。大单行、大段落、大代码块的布局成本无法由“用LazyColumn”自动解决。

先分别测导入、首帧、可交互、最终装饰完成、最长主线程停顿和内存；参考机上的2秒候选值目前未证明可达。后台只处理不可变快照，回主线程应用的span/块也需限预算。禁止用重建EditText、整篇setText、截断正文或降低1MiB上限换取表面流畅。[Android官方响应性建议](https://developer.android.com/topic/performance/anrs/keep-your-app-responsive)同样要求将重计算移出UI线程并控制主线程工作量。

桌面仍每次更新执行 `renderMarkdown`，包括源码模式；CodeMirror/笔记内查找也要观察大文本预算。该路径已确认，当前平台停顿程度未测；是否将桌面优化正式纳入M2见Q1。

### R5：离线UI拆锁会打开新的并发窗口

[MemoModel](../../android/app/src/main/java/app/djhx/memo/MemoModel.kt)的Devices仍调用通用 `action`，它设置全局busy；[AccountSettings](../../android/app/src/main/java/app/djhx/memo/AccountSettings.kt)的返回、tabs及多个入口依赖该busy。网络本来经IO线程执行，问题主要是状态耦合，不能称为已证实“网络直接跑主线程”。

全局busy同时承担了部分操作串行化。拆除后至少需要：

- Devices独立的loading/data/inlineError/真实in-flight状态，内存缓存按profile＋会话版本隔离；重新登录同一profile也使旧回执失效。
- 读取动作携带发起时profile锚点；离页、切空间、登出后旧结果和旧错误不得回写或弹到编辑页。
- 保存、切空间、登录/注册、吊销等写动作继续有各自的互斥/请求身份，不能把按钮全部放开后依赖“通常不同时操作”。不复制core的鉴权/冲突规则。
- 对真实未结束请求设有界上限。逻辑取消只是忽略结果，JNI阻塞调用仍可能占着线程/活动租约；不能连续刷新无限堆积，也不能提前放行安装屏障。
- 本地编辑和新固定范围搜索无需等待设备列表成功；保留0.1.13的搜索锚点、来源快照、迟到响应保护和Ctrl+W保存链。

重要写操作仍以实际回执为准；永久删除、安装授权等确认继续保留。把所有错误都改成toast或把网络请求一律忽略，同样不符合目标。

### R6：新装默认目录与旧安装路径的优先级需覆盖两个入口

[生产NSIS模板](../../desktop/src-tauri/windows/installer.nsi)当前在 `$INSTDIR` 为占位值时才设置默认并调用 `RestorePreviousInstallLocation`；显式 `/D` 可以绕过该分支，交互目录页也能进一步修改路径。[NSIS官方说明](https://nsis.sourceforge.io/Docs/Chapter3.html#installerusagecommon)明确 `/D` 设置INSTDIR并覆盖默认来源，且是末尾参数。

目标必须把“检测到已有安装”作为独立事实，再决定允许的最终目录，不依赖占位值推断新装。要同时处理 `.onInit` 和目录页离开校验，统一规范化后的路径比较，不能因大小写、尾分隔符、跨语言或静默模式创建第二套安装。

已确认旧路径继续升级；不同 `/D` 的具体拒绝/提示方式仍待Q4定稿。新装自定义目录和 `/D` 必须继续有效。保留INSTALLIDENTITY/注册表键“简记”、binary、卸载识别与签名身份，显示名已是阳墨随记/DJHX MEMO，不需要再改这些身份字段。

### R7：原件遗失后已确认新母版，受管资源接入完成

旧附件预期哈希为 `b597731e5496bb1cd92fac662950668948237bee8fdae93e110eda1c2ae81f65`，原件已遗失。维护者先授权根据PNG重绘，随后明确确认采用并要求完整多端替换。[已确认母版](../../assets/brand/sources/jade-ivory-v1/README.md)新SHA256为 `1970cef1201bc15581156631df4c403c217626b92f7f30944b7e0d8296771cb4`；PNG依据和最初预览保留，它不是原文件恢复，不沿用旧provenance声明。

0.1.13基线仅支持旧包；本轮已按[ADR-0020](../adr/0020-jade-ivory-brand-render.md)新增固定resvg-js2.6.2开发渲染工具、jade-ivory-v1包和受限读取器。源/整包/成员哈希、完整62项图形路径集合和ZIP重复/越界防护均校验，加入名称后68项输出。旧sunrise63项先归档，可恢复性与黑白托盘原哈希已验证；普通Python适配/客户端/官网构建不依赖渲染工具，不新增运行时依赖。

Android需拆背景/前景与单色层，系统遮罩/着色仍生效；“中心放大”服从安全区，不能保证桌面与安卓像素占比完全相同。[Android官方图标规范](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive)规定108dp图层与中央66dp安全区域。黑白托盘字节及选择逻辑保持；官网已构建并核对引用，线上部署另验。

### R8：更新目录schema字段不是当前自动更新故障

[0.1.13补充核实](../releases/0.1.13-validation.md)与源码一致：更新验证器仍要求 `schema_min/schema_max==3`，并未拿实际SQLite user_version=4比较，因此不能把它当作“0.1.13无法自动更新”。真实数据库的高版本保护仍在 `db::open`。

这些字段也不能简单改称“目录格式版本3”：信封与payload格式自有版本字段。应记录为当前固定兼容标记与真实库范围检查之间的机制缺口。0.2.0不新增迁移时保留兼容，不单改成4或借小版本号扩大迁移；将来接入真实范围门禁需单独设计旧更新器桥接。

### R9：Release、设备验收与线上推广是三个事实

公开0.1.13已确认，发布记录待补不等于Release未发布；反过来，公开资产也不能补齐39项用例或三端安装通过。0.2.0至少保留这些发布关口：test结果单独核对（release job当前不依赖test）、APK证书读取失败warning的补验、真实覆盖安装、目录签名和官网下载检查。

目录签名已按ADR-0019在CI，不能沿用旧“全部本机签名”口径。catalog序号从线上读取＋1，不应看到Release有catalog-10就预设0.2.0必为11；需核实最终线上值，并防止未部署期间重跑/并发签发使用同一序号。首页200不代替签名目录/下载链接验证。本轮不修改workflow或生产服务。

## 5. 修订后的实施与验收顺序

1. **基线与资料**：0.1.13公开状态及未验收项已补记，新SVG已确认。继续收敛Q1–Q4，固定参考机与样本；应用运行依赖与版本不随品牌工具升级。
2. **W1原型**：优先源码页，分解正则、查找span、列表扫描、全文复制与布局成本。覆盖128KiB两侧、960,000字节/20,000行历史结构、1MiB、单长行/巨段/巨代码块；保留精确正文/选择/撤销/保存。最坏结构未达目标时先评审方案，不直接重写编辑器。
3. **W2独立状态**：Devices区域状态、会话版本、请求上限和局部写锁；断网/黑洞/401/离页/同账号重登/更新屏障下验证。独立复核会话/取消边界，不复制同步规则。
4. **W3排版样例**：在W1预算内比较自动折行、段内LF、空行段落与列表续写，验证触摸/查找定位。不能等M2做完再用大量段距span把它拖回去。
