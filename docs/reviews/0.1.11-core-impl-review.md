# 0.1.11 core 实现交叉评审（C4 迁移 + search_notes）

- 状态：开发期交叉评审记录，2026-11-20。对象为 core 0.1.11 实现（迁移 0004、`db::search_notes`、`search.rs`、`Engine::search_notes`、新增测试）。按 [AGENTS](../../AGENTS.md) "同步、迁移与鉴权变更必须经过交叉评审" 执行。

## 结论

**迁移 0004 与 search_notes 实现通过交叉评审，可合并。**

## ① 迁移 0004：安全

- C4 修复正确：`DROP TRIGGER notes_update` 后重建，保留 `AFTER UPDATE OF content` 并新增 `WHEN old.content IS NOT new.content`；delete+insert 维护逻辑与 0002 一字未变。根因是 `db::put` 的 UPSERT 恒把 content 列入 SET，`WHEN` 正确拦截纯元数据更新（ack/set_deleted/purge_state），内容真变化时仍维护索引；purge 清空正文也照常删索引。
- 未修改已发布迁移：0001/0002/0003 零改动，0004 为纯追加。
- 备份/checksum 对 0004 生效：旧库 v3→v4 会先备份 `before-v4.sqlite`；`execute_batch` 在 Immediate 事务内 DROP+CREATE 原子，无半迁移态。

## ② search_notes 语义：正确

- 字面匹配与 product-v1 §7 一致：`to_ascii_lowercase` 仅 ASCII 折叠、字节长度不变、偏移与原串一致；`% _ \` 转义后参数化 LIKE。
- 两段式召回正确：≥3 字符且无通配符走 FTS5 trigram 候选（内层无 ESCAPE 可用索引、大小写不敏感为真匹配超集），外层带 ESCAPE 的 LIKE 是权威过滤器；<3 字符回退全表 LIKE。两条路径语义一致，无 `MATCH` 语法，无 SQL `LIMIT` 预截断。
- UTF-8 边界安全：切片源自字符边界或 `char_to_byte`/`byte_to_char` 安全钳制；空命中兜底不 panic。
- scope 枚举正确：current/all_local/account/space_ids，`retain(kind != "recovery")` 统一跳过恢复空间；绕过 `profile()` 守卫但只读（SELECT）不写库、不触发同步，无脏写。
- 排序/截断正确：score DESC → updated_at DESC → note_id ASC；`truncated = len>50` 后截断。
- 无注入面，`list` 未破坏。

## ③ 测试覆盖：有效（已补两处缺口）

- `migration_backup_checksum_and_newer_schema_are_enforced` 的 user_version 断言 3→4 必要且正确。
