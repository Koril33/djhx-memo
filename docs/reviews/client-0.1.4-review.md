# 0.1.4 同步、迁移与客户端交叉评审

日期：2026-11-11。原始开发提交为 `1634835`，相对 `7733902` 检查。维护者在本次发布任务中明确确认单条彻底删除及协议 2 配套服务端升级。行为依据为[增量契约](../../spec/permanent-deletion.md)，最终平台验证另见[发布记录](../releases/0.1.4-validation.md)。

## 分工与发现

核心与服务端分别由未编写原始实现的独立协作者审查；整合协作者复核修复，并执行完整联调。Windows 协作者另行审查桌面确认目标、永久标记后的救援缓冲、生命周期屏障和原生交互。此记录不以原分支的自检代替交叉评审。

发现并修复：

- 核心旧冲突成功回包丢失后，其他设备可以先彻底删除冲突副本。旧确认重放原会把该副本的 `purged` 改回 `none`，有续写时还会恢复正文。现在确认保留权威永久标记，不自动生成替代副本；指向已删除目标的旧别名也不能绕过保存、恢复及任务勾选限制。整合协作者独立复核 `db::acknowledge` 与重定向后屏障。
- Android 切换空间后，旧空间迟到的永久删除结果原会按相同 note ID 被套到新空间，导致新编辑被清空或锁定。现在请求前捕获 profile，返回后复核当前空间、编辑空间与 ID；两项仪器回归先在原代码失败，再在修复后通过，整合协作者独立复核修复。
- 完整服务端场景测试中，位置参数 `Note` 夹具没有适配新增字段，导致整套测试无法编译。改为具名初始化，保留所有业务断言。
- 服务端新增测试有三处未检查的关闭错误，导致完整 lint 失败；逐处处理，没有屏蔽告警。
- 既有丢包代理未转发协议请求头，协议升级后不能有效运行原联调。补传 `X-Memo-Protocol`，保留全部场景断言。

新增回归覆盖已永久删除冲突副本的旧确认重放（含有/无续写）、待删除目标状态、旧别名，以及含永久标记和幂等记录的备份恢复。修复未改变 API、schema 或已发布迁移。

## 复核结果

- 核心：格式、拒绝警告的 Clippy、27 项单元测试通过；旧库升级、迁移校验及高版本拒绝继续有效。
- 服务端：完整格式、vet、`go test -race ./...`、lint 通过。复核账号隔离、事务内凭据复验、版本条件、幂等及跨操作 ID 复用、不可逆标记、同事务的 changes/head/processed_ops、提交后通知及导出排除，未发现其他确定阻断项。
- 整合：9 项真实 Go HTTP 联调全部显式执行通过，包含新增彻底删除及丢包重放；CLI 在线备份、停服恢复、epoch 轮换及旧推送拒绝通过。服务端另行运行加密备份 smoke，通过损坏拒绝、权限、留存及隔离 rsync。
- 既有 core/server 迁移内容与主分支一致，只追加新迁移；没有重写历史或弱化既有断言。
