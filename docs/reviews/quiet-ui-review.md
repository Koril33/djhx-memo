# 0.1.1 统一界面预览独立复核

- 日期：2026-11-08。
- 范围：[产品规范 §11](../../spec/product-v1.md#11-011-界面预览轻量与统一)、桌面与 Android 展示入口、共用图标及安装升级身份。
- 分工：桌面与 Android 由不同协作者实施；桌面协作者独立只读复核 Android，品牌协作者独立复核桌面并在 Windows 原生构建和验收，整合者复核共同资源、两端编辑实例与 Ubuntu 原生窗口。此记录不替代既有同步、迁移、鉴权评审。

## 发现与处理

| 发现 | 修正与复核证据 |
| --- | --- |
| Android 若通过条件分支替换源码视图，预览往返将丢失原生撤销记录 | 保持同一 AndroidView/EditText，隐藏时禁用焦点与读屏、结束组合输入；返回时恢复可见性。设备断言检查同一实例、正文及原生 Undo，桌面也保持 CodeMirror 实例 |
| 恢复空间都显示同一短标签，难以区分恢复批次 | 空间设置保留来源与按偏好格式化的批次时间；补充当前空间的 selectable/RadioButton 语义，不依赖装饰性对勾 |
| 移动端救援与鉴权按钮在窄屏横排拥挤 | 救援按钮采用 FlowRow、鉴权操作竖排；保留短标签和全部原操作 |
| Android 320dp、130% 英文大字下，固定等分设置标签在词中换行 | 窄屏/大字时采用现有 Material 横向滚动控件并保持短标签单行，正常宽度保留等分布局；320dp/130% 实际确认英文不拆词且可滑到 Data。修复后重新构建、签名及完整设备验证，不把初稿状态当作通过 |
| 浅色次级文字初稿在纸白上对比度不足 | 统一提高至 #6B726B；在 #F7F6F2 / #FCFBF8 上的计算对比度分别约 4.58 / 4.78，最终两端资源一致 |
| Android 独立弹出窗口可能沿用初次语言 | 主菜单与偏好菜单显式提供当前 Context/Configuration；MemoAlertDialog 在标题、正文及两个按钮插槽恢复当前配置。新增菜单与已有设置切换设备断言保留，失败经定位修复后重跑 |
| WebKitGTK 将原生 details 的 summary 暴露为 unknown | 三处 summary 显式标为 button，局部注明 Svelte 冗余角色告警的兼容原因；最终 Ubuntu AT-SPI 实际读取到“更多操作”“笔记操作”“保存与同步状态”button |
| Markdown 任务勾选也需要统一图标且不能开放用户 SVG | 仅生成器中的固定 check 资源进入控件；用户 HTML/SVG 仍转义。新增只读状态、SVG 转义与任务图标回归，既有前端测试保留 |

## 保留的行为

静态差异复核确认 MemoModel/CoreGateway、core、server、协议、迁移与凭据身份未变化。菜单只调用既有操作：空间导出仍遵循当前列表/回收站范围，笔记文字导出保留救援作用；保存、切换、导入、设备吊销及失败处理没有移入另一套 UI 同步规则。

删除/恢复、导入来源与目标、设备吊销、注销及保存失败的必要事实和确认保留。低频功能收进菜单后仍有本地化名称；普通按钮保持桌面 36px、移动端 48dp 点击范围与提示。错误、凭据失效、冲突、只读恢复和本地保存失败继续可见，不折叠成正常成功状态。

图标采用锁定 Lucide 1.70.0 的本地 SVG，不请求 CDN；源 SHA、完整 ISC/MIT 许可和两端生成资源通过生成器检查。品牌 Logo 仍沿用原母版；未新增运行时依赖、应用标识或数据目录。

## 结论与边界

修复后只读复核未发现新增阻断。Ubuntu 与 Windows 的实际编辑、预览撤销、菜单删除恢复、偏好和覆盖安装结果见[桌面验证](../desktop-ui-preview-validation.md)，Android 完整设备结果见[Android 验证](../android-ui-preview-validation.md)。截图均为隔离的演示内容；Windows 原用户目录在测试后恢复并校验原笔记哈希。

这不是 v1 发布批准。物理 arm64/API29、Ubuntu24.04 原生桌面、完整中文输入法/大字与辅助技术矩阵、三端同账号 GUI 与连续 7 天使用仍需补足；静态复核不等同于这些设备验收。

本轮另保留一项已观察到的视觉限制：Android 320dp/130% 字号下，账号表单次级注册按钮文字在视口底部部分裁切；实际仍可进入注册表单。证据及范围见 Android 验证记录，不能将这项边界表单显示计为完全通过。
