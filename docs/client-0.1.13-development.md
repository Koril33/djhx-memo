## 3. W1：桌面空白页与会话状态

### 3.1 状态与展示模型

建议独立维护 `editorPage: welcome | draft | note`，另有短暂的会话过渡标记。`source/preview/split` 等显示偏好仍属编辑器呈现模式，不与会话状态混用。具体代码标识符可按现有风格调整，状态含义不可合并。

```mermaid
stateDiagram-v2
    [*] --> welcome: 冷启动
    welcome --> draft: 新建
    welcome --> note: 打开或导入成功
    draft --> note: 首次本地保存确认
    draft --> welcome: Ctrl+W 保存成功
    note --> welcome: Ctrl+W 或删除当前笔记成功
    note --> welcome: 成功切换空间或分区
    draft --> welcome: 成功切换空间或分区
```

所有离开编辑会话的箭头都经过保存/输入保护；失败维持原会话。隐藏是窗口生命周期，不是此图中的新笔记状态：X 可直接隐藏打开的笔记；空白页 Ctrl+W 隐藏后，恢复仍为空白页。进程已经退出后的重新启动属于冷启动。

欢迎页可提取为小型组件，只接收可用性与动作回调，不访问 core/凭据。沿用既有颜色与排版，中文可用“新建笔记／搜索笔记／关闭窗口”，英文可用“New Note／Search Notes／Close Window”。关闭去向按实际托盘状态提示；不添加教程流、新闻、用户正文或版本升级弹层。

欢迎页挂载时清理编辑器查找 API、pending find query、旧文档选择和保存定时器；列表可以保留原筛选/滚动，但没有一个假的选中笔记。焦点落在欢迎页可操作项，Tab 可遍历；列表重新点击可打开笔记。只读空间中的新建仍禁用，不能通过 Ctrl+N 或托盘入口绕过。

### 3.2 安全关闭当前文档

建议把逻辑放在一个受测的会话操作中，由 Ctrl+W 调用，操作顺序为：

1. 检查当前 page、模态、composing、安装锁与会话过渡标记。`event.repeat` 直接忽略；过渡期间的新关闭按下不排队。
2. 对 draft/note 建立短暂输入保护；IME 组合期不启动快捷键导航，其他导航先沿既有机制完成组合输入。输入保护不能让最终组合文本丢失。
3. `await editor.flush()`，等待真实本地提交与最新 generation。flush 不等待云端同步成功。
4. 确认缓冲与已提交基线一致，或属于既有无需保存的空白草稿；然后结束会话、切 `welcome`、清理引用和选中项、设置焦点。
5. 任一步失败，保留原 page/正文/光标/错误及救援出口；释放本次过渡锁。不要先清空再尝试重读。

可复用 EditorSession 现有输入锁/flush 原语，但“关闭当前文档”不能发送 `finish_lifecycle`，也不能等待一个不存在的原生关闭 ID。`finishLifecycle` 仍服务真正的窗口隐藏/退出。保存中的正常自动提交、连续输入的 drain、重复 create request ID 规则保持不变。

单次 Ctrl+W 从 note/draft 只能到 welcome；用户释放并再次按下，且前次过渡已结束，才允许调用 `request_hide`。避免 async handler 在 await 后重读 page 并再次分支，从而一次按键做两件事。空白页 Ctrl+S 不启动 create。

### 3.3 入口清单与失败处理

| 入口 | 实施要求 |
|---|---|
| 首次 `refreshState`、重启 | 加载选中空间和偏好，不自动建立草稿或选第一条；显示欢迎页前仍保留正常初始化错误/重试 |
| `newNote`、`memo-new` | 旧缓冲保存成功后进入 draft；托盘唤起窗口与草稿创建顺序协调，不能被随后一次 state 刷新清成 welcome |
| `selectNote` / 搜索跳转 / 导入成功 | 读到正确空间的最新笔记后进入 note；旧异步回调不得覆盖新会话 |
| `changeSection` / `switchProfile` | 保存成功、目标切换确认后 welcome；清理旧编辑引用，但不擅自重置语言/主题或持久账号选择 |
| 当前笔记普通删除/彻底删除完成 | 本机操作确认后 welcome；批量逐项检查当前 ID 的结果；失败保留可恢复上下文 |
| 普通删除撤销 | 严格原 ID/代次恢复列表，不自动重开笔记；过期撤销不伪报成功 |
| 后台刷新、重定向、远端删除 | 维持现有未提交缓冲/代次冲突/NOTE_PURGED 救援，不直接清空组件 |
| X/Alt+F4/托盘退出、更新安装 | 既有 lifecycle 与安装屏障优先；会话过渡与其串行，共用最终缓冲确认，避免双重清理 |

区分“保存失败”“core 切换失败”“core 已切换但 UI 刷新失败”。最后一种不能假装仍在旧空间正常编辑；应保留已保存快照、禁用错配编辑并提供状态重载。不得为补救 UI 失败自动把旧正文创建到新空间。

## 4. W2：固定搜索范围与接口

### 4.1 固定集合及快照

一次请求在 core 中从同一个 registry 快照得到 selected 与 profiles，取所有 local profile，加 selected 恰为 account 时的一个 profile，按 profile ID 去重，排除 recovery。然后在锁外开库查询；不要在查询所有账号、打分或 top 50 之后才过滤其他账号。

UI 删除所有范围选择、回收站 checkbox、相关组件状态和空白占位；若发现旧偏好存储，只使其不再影响查询，不为当前未持久化的控件新增偏好迁移。当前列表的 `trash`/deleted 分区不参与范围计算。搜索按钮与欢迎页快捷键提示使用同一入口。

“当前账号”就是 registry.selected 对应的 account。选中本机或恢复空间时没有搜索账号；不读取最后登录账号作为补充。当前账号过期时仍可搜其本地缓存；注销切回本机后立即作废其搜索回执。跨空间打开一个本机结果后，后续搜索也按本机上下文执行。

### 4.2 core JSON 目标接口

为让两端只提交同一个搜索意图，新增明确范围值 `local_and_current_account`；旧 `current/all_local/account/space_ids` 行为供已有调用保留，不需要两个并行搜索再由 UI 拼接。

```json
{
  "action": "search_notes",
  "profile_id": "selected-profile-id",
  "query": "1",
  "scope": {
    "kind": "local_and_current_account",
    "include_deleted": true
  }
}
```

| 参数/行为 | 目标约束 |
|---|---|
| 根 `profile_id` | 新模式必填，表示 UI 发起时的 selected profile；与 core 快照 selected 不符时返回 `PROFILE_CHANGED`，不悄悄搜索另一个账号 |
| `scope.kind` | 新值必须由 core 显式实现；不能依赖当前代码未知 kind 回落到 current 的分支 |
| `scope.space_ids` | 新模式不得同时提供，避免显式 IDs 覆盖固定集合；混用返回 `INVALID_REQUEST`；旧模式的 IDs 规则保留 |
| `include_deleted` | 沿用接口的普通删除维度；本版两端固定发送 true，不再暴露开关；不改变旧模式默认 false |
| `query` | 保留原字面匹配；空 query 返回空 hits、truncated=false，由 UI 显示输入提示 |
| 输出 | 仍为 `{hits:[SearchHit],truncated}`；不返回正文全文、凭据或所有账号信息；不新增分页、部分成功 DTO |
| 排序 | score 降序、updated_at 降序、note_id 升序，完全相同时 profile_id 升序；top 50 在合并之后执行 |
| 失败 | 沿用稳定错误码；任一目标开库/查询失败则整次失败，UI 提供重试；不忽略坏库冒充完整结果 |

锚点校验与集合枚举应在同一 registry 快照内完成，不能先调用一次 `profile()`、释放锁后再取另一份 selected。查询期间用户可切空间；已开始的只读查询可按旧快照完成，但 UI 必须丢弃其迟到结果。不要长时间持有 registry 锁阻塞切换或保存。

这是现有 UniFFI `MemoApp.invoke` JSON action 的扩展，没有新导出方法；Android 仍需重建实际 core/JNI，不能只更新 Kotlin/UI。协议、server schema、local schema 均不因此变化。开库继续既有迁移与校验机制，“只读搜索”指不修改笔记、凭据或触发同步，不是承诺 SQLite 打开绝无初始化写入。

### 4.3 来源数据与结果身份

本版保持 SearchHit 字段不变：使用 `profile_id / space_kind / deleted`，加 UI 请求时捕获的 ProfileInfo 白名单快照解析来源。两端按同一规则构造显示：

- 本机显示“本机空间”；若未来存在多个自定义本机空间，可追加其安全显示名。
- 账号显示 `username · server host`，例如合成值 `alpha · notes.example.invalid`；缺用户名时用 profile.label，缺可显示主机时用“账号空间”降级文案，不使用凭据或文件路径填充。
- 从 URL 只取安全主机/必要端口及区分实例所需的基础路径，丢弃 userinfo/query/fragment；完整来源通过 tooltip/无障碍名称可读。
- 普通删除另显示“回收站”，不能覆盖账号来源。以 `(profile_id,note_id)` 作为结果身份、选中项和打开目标；分隔字符串要保证无歧义。

请求过程中 profile 名称/账号上下文改变时作废来源快照并重查，不对新 registry 按 note ID 猜来源。不得把来源元数据、搜索词或摘要输出到日志；评审截图只用合成内容。

### 4.4 异步状态、错误与打开

搜索状态至少区分 empty-query/loading/success-empty/success-hits/error；旧结果若暂时保留须明确为旧状态，不能在新查询失败后显示成新成功。重试沿用当前有效 query 与范围，关闭后重试回调不能重新打开面板。

每次查询携带本地请求身份：面板会话、查询序号、范围版本；范围版本在选中空间或参与空间/来源元信息变化时递增。`event_seq` 用来发现需要刷新状态，不能把每次无关轮询都变成一次抢焦点的搜索。150ms 防抖可沿用，IME Enter 不得误打开结果；快速输入/切空间/关闭后清理 timer 并作废旧序号。Job/Promise 取消不视为底层 JNI/core 已停止。

打开结果使用单独的会话过渡：

1. 捕获 hit 的复合身份与 query，确认它属于当前仍有效的搜索请求。
2. 保存旧编辑缓冲；失败停留并保留缓冲，不先切空间。
3. 必要时切换到目标 profile，取得最新 state/note；不得把搜索摘要写回正文。
4. 根据最新 `deleted/purge_state` 决定正常/回收站只读上下文。已彻底删除或不存在时提示并刷新，不能自动恢复。
5. 打开最新 note 并注入字面 query 定位。内容已变化为无命中时明确显示未找到，不回放旧正文；失败后恢复可用 UI 状态。

桌面现有 `openGlobalSearchHit` 无条件 `trash=false` 的行为需改为正确的回收站上下文；Android 也同步核对。保存成功后 core 切空间成功、取笔记失败的情况按 W1 的状态恢复处理，不擅自回滚账号或另建副本。

## 5. W3：桌面结果布局与两端展示

### 5.1 已确认的根因与修正原则

[评估 §4.4](client-0.1.13-assessment.md#44-桌面挤压的实际原因)记录了原 CSS 在 3/10/50 条合成结果下的测量：10/50 条结果从内容所需高度压到 36px，摘要为 0，相邻内容重叠；仅在探针中禁止条目收缩即可消失。这是定位证据，不是产品修复或 Linux 验收。

实现时让结果行保持自然内容高度，列表负责纵向滚动。纵向 Flex 的条目应不收缩，父容器的 flex/min-height/overflow 链保持一致；也可用更适合自然行高的等价布局。不得硬编码探针的 112.375px 行高，不通过隐藏元信息或提高最小搜索字数规避。

标题最多一行，摘要最多两行；元信息可换行。选择背景、点击区、键盘焦点环须覆盖整个实际条目，不能只有文字溢出的区域可点。容器随窗口高度分配空间，最小窗口也能到达末条与截断提示；中英文、长账号、大字和缩放不依赖固定单行元信息。

### 5.2 交互与 Android

桌面上下键、Enter、Escape 保留，只有选中项离开可见区时滚动至可见，不因每次结果重绘把用户滚回第一条；空列表或查询更新后修正索引，不能访问越界结果。模态框焦点陷阱和 IME 守卫继续有效。

Android 的 LazyColumn 不照搬 CSS 修复；检查去掉过滤控件后展开区的高度与键盘遮挡。来源/回收站/计数/时间可分行，标题与摘要保持有界显示；长来源和系统字体放大不能挤成零宽正文。复合 key 必须与桌面语义一致。

## 6. W4：Android Markdown 列表编辑

### 6.1 平台差异与本版边界

桌面使用 `@codemirror/lang-markdown@6.5.2` 的 Enter 命令，Android 是原生 EditText，没有该命令。后续实现保持原生编辑器，只增加局部编辑能力。

补充源码核对发现，CodeMirror 默认还会在某些第二空项场景先将紧凑列表变成松散列表，并可重编号后续项。**Android 本版按目标规范的简单空项退出处理，桌面不改**；不能把“对齐基础列表方向”误解为移植其全部内部行为。

必做语法为 `- + *` 与 1～9 位数字加 `.`；保留确认有效的当前列表项空格缩进。参考 [CommonMark 0.31.2 列表项](https://spec.commonmark.org/0.31.2/#list-items)识别 Markdown 上下文；编号边界、空白与代码上下文不靠“这一行以减号开头”判断。

非本版语法（任务项、引用、`)` 编号、复杂多行项/层级操作、Tab 混排）走原生换行；明确识别的嵌套普通项可沿用当前缩进，不增加升降级命令。围栏内、缩进代码、转义符号和主题分隔线不处理。无法可靠判断时普通换行，正文仍可完整手写。

### 6.2 建议结构

将逻辑分成“判断与编辑计划”及“原生输入适配”两层：

| 层次 | 输入/输出及职责 |
|---|---|
| 纯命令 | 接收正文快照、UTF-16 选区、已确认的回车意图/上下文；返回不处理，或局部 replacement range、插入文本、目标光标；不做持久化 |
| 上下文识别 | 判断列表/代码/引用/任务及缩进；仅为回车计算，不在每次 TextWatcher 全文扫描；可缓存但必须按文本版本失效 |
| 输入适配 | 在 EditText/InputConnection/硬键盘路径中选择一个统一命令入口，验证 composing 与当前快照，至多应用一次 |
| 原生应用 | 用局部 Editable 替换和 Selection 更新保留 span；批处理防止中间状态触发保存，保留原生撤销记录 |
| 保存/高亮 | 最终文本继续经原 onEdit/保存路径；高亮只装饰，不再次触发续写，不清空编辑历史 |

纯 Kotlin 命令可作为内部文件，具体名称由实现者确定。默认不新增解析依赖或 core/UniFFI 编辑命令；若现有能力无法可靠区分上下文，先记录原型结果，再按 ADR 评估必要依赖，不暗中引入整套 Web 编辑器。

### 6.3 输入事务与降级

- 硬键盘 Enter 的 DOWN/UP、软键盘 `commitText("\n")`、可能的 editor action/sendKeyEvent 都需观察真实触发路径，只消费一次；未处理分支必须恰好执行一次原生换行。
- composing active 或候选确认时不执行续写；组合结束后的真实回车另行判断。不能用延迟任务在 compositionend 时补一个未经用户发出的 Enter。
- 只在光标为折叠选区且位于逻辑行末时自动处理；行中/选区/批量粘贴遵原生行为，避免复制整个前缀到错误位置。
- 新行标准前缀用单个空格；保留上一行用户正文，不 trim 全文、不批量修正编号或换行。空标记退出只移除该行有效前缀并留普通空行。
- 局部替换应作为一次逻辑编辑进入撤销；`beginBatchEdit/endBatchEdit` 本身不证明撤销已经合并，须用实际软键盘、硬键盘和原生撤销验证。
- 新增列表逻辑不能引入每次输入全量重排。优先在当前输入回调中用可靠上下文生成局部编辑计划；上下文无法及时确认时立即普通换行，不等待后台计算。后台上下文缓存须按空间、笔记、文本版本失效，不能迟到后再补前缀或撤销用户后续输入。既有 M2 单独保留，不把本版记为其整体修复。
