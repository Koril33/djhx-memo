# 测试用例描述（业务功能与联动）

本文以文字描述 v1 备忘录应用需要覆盖的测试范围，不含测试代码。目的是：从每个业务功能及其相互关联入手，把「测什么、边界在哪」说清楚，最终找出软件的极限、边界与现存问题。所有描述均以 [产品契约](../spec/README.md) 为准，具体断言见 [一致性场景](../spec/conformance/scenarios.md)。

## 1. 目的与范围

- 覆盖三端（Windows / Linux / Android）与同一套服务端 + 核心库（core）。
- 覆盖未登录本地笔记、账号、云同步、恢复、导入、导出、搜索、托盘、展示与性能。
- 重点补足两类：单功能各自的行为边界，以及跨功能联动（编辑×同步、导入×同步、账号×同步等）。
- 本文只描述「需要测什么」与「期望验证的边界」，不写测试代码、不替代自动化测试或人工验收记录。

## 3. 单功能测试用例描述

### 3.1 未登录本地笔记
- 新建：空白草稿不落库，输入首个非空字符后才持久化；「创建成功但 UI 未收到响应」重试时，只能产生一条笔记（`local_requests` 幂等，见 LOCAL-06）。
- 编辑：清空正文不自动删笔记；中文组合输入不被中断；复制 / 粘贴 / 撤销正常。
- 删除 / 恢复：删除进回收站（墓碑 + 正文均保留）；普通搜索不返回回收站；恢复是「基于已知版本的正常修改」，恢复时遇远端编辑也要走冲突副本；v1 无永久删除。
- 搜索：1～2 个中文字、英文混合、ASCII 大小写不敏感；`%`、引号等 FTS/SQL 特殊字符按字面匹配、不注入、不报错；trigram 对少于三个字符子串的回退行为；拼音 / 模糊 / 词义搜索明确不支持。
- 导出：全部未删除 + 单独回收站；`<note-id>.md` + `manifest.json`；先 flush，失败时不得显示「全部成功」；不覆盖目标路径既有文件；manifest 不含密码、token、邀请码或绝对本地路径。
- 本机空间与账号空间独立：未登录内容绝不后台自动上传。

### 3.2 Markdown 编辑与预览
- 标题派生：去行首标记、最长 80 个 Unicode 字符、空内容显示「无标题」；列表按更新时间倒序 + note ID 升序稳定排序。
- 源码 / 预览一致性；任务勾选只改对应 `- [x]`，代码块内相同文本不可勾选；旧预览不能覆盖新代次（EDIT-03）。
- 代码围栏按语言离线着色；未知语言或超过处理上限的代码仍显示为普通代码块；着色不改变正文、缩进、选区或输入法组合。
- HTML 安全：`<script>`、嵌入页面、外部图片自动加载、危险链接协议全部禁用；`http/https` 外链交系统浏览器打开；不向 Markdown 内容授权 Tauri 命令（EDIT-04）。
- 表格、数学公式与复杂扩展暂不保证（边界）。

### 3.3 本地保存状态机
- 300ms 防抖、连续输入最长 1 秒提交；失焦 / 切换笔记 / 隐藏窗口 / 进入后台 / 正常退出时立即 flush；只有事务提交成功才显示「已保存到本机」。
- 三态「保存中 / 已保存到本机 / 保存失败」；失败（磁盘满、权限、数据库故障）保留内存内容，提供重试与「复制 / 导出救援」。
- 系统强杀前未提交的输入不承诺恢复（边界，见 LOCAL-03）。
- 云状态六态（仅本机 / 待同步 / 已同步 / 离线 / 需重新登录 / 需恢复处理）语义校验。

### 3.4 账号
- 注册：邀请码一次性消费、默认 7 天过期、可提前吊销；并发两次注册只成功一个（AUTH-03）；响应丢失不重复消费邀请码、不留半个账号；用户名 3～32 位约束；冲突返回 USERNAME_TAKEN。
- 登录：token 只返回一次明文、服务端仅存哈希、默认 90 天过期、无 refresh token；限流（15 分钟 5 次失败 → 429 + Retry-After；注册每小时 5 次/IP）；账号不存在与密码错误返回同一错误。
- 注销 / 吊销：离线注销要显示「远程吊销尚未完成」；吊销 A 后 A 离线写内容、联网后 API 拒绝 + SSE 断开、本地内容保留、重新登录后继续（AUTH-02）；重复吊销返回成功。
- 凭据存储：系统凭据库不可用时 token 仅驻进程、重启需重新登录、绝不落明文文件（LOCAL-04）。

### 3.5 本机笔记导入
- 只复制未删除笔记、生成新 note ID、原笔记保留；「同一来源笔记 + 同一保存代次」重复导入不产生重复目标（LOCAL-02）。
- 中断后可恢复；导入映射与待同步操作同事务落盘。
- 导入后原笔记继续编辑不与副本联动；再次导入新代次属于新副本、操作前显示数量。

### 3.6 云同步
- 不变量：本地先持久化再发送；只用服务端 rev 判定并发（不用客户端时间或 ID）；原笔记版本不匹配时保留权威状态、传入内容保存为冲突副本。
- Push：`base_rev` 语义全表（不存在 + `0` / 不存在 + `>0` / 大于当前 / 等于当前 / 墓碑 `already_deleted` / 其余冲突）；`op_id` 幂等（同 id 同内容返回原结果，同 id 不同内容 `OP_ID_REUSED`）；每请求 ≤50 项且编码后 ≤8MiB；逐项成功 / 失败、结果顺序与请求一致。
- Pull：`cursor` / `until` 分页；`has_more=false` 时 `next_cursor=H`；页间并发新 seq 留到下一轮；`cursor>head` 返回 `CURSOR_INVALID`（不静默跳）；应用一页中途崩溃则整页回滚、cursor 不变（SYNC-14）。
- 冲突：`stale_edit` / `stale_delete` / `edit_after_delete` 三种 reason；冲突副本永远 active；「删除未执行，内容已保留为冲突副本」；原笔记已删 + 修改 → `edit_after_delete` 可见副本（SYNC-07/08）。
- 继续编辑：冻结代次 G vs 最新可见代次 H 的四种确认处理（accepted 且 H=G / accepted 且 H>G / conflict 迁移焦点 / already_deleted）；迟到冲突确认不能覆盖副本已有的独立本地编辑（SYNC-05/06）。
- 重试：指数退避 1、2、4、8 秒、最高 60 秒 + 抖动；网络恢复和手动重试可提前触发；永久错误不阻塞其他笔记。
- SSE / 兜底：SSE 只发更新信号，前台每 30 秒兜底拉取；Push 后通知前崩溃最终靠兜底收敛（SYNC-21）。

### 3.7 服务端恢复与 epoch
- epoch 不匹配 → 禁止 Push → 旧库保全为只读恢复空间 → 新副本从零拉取；旧内容以新 ID 导入、不重放旧 op_id、不静默覆盖新权威数据（RECOVERY-01）。
- epoch 相同但 cursor 超前或数据异常 → 进入安全恢复流程，不把 cursor 改为 0 后自动重放原 outbox（RECOVERY-02）。
- 恢复同时使 token 失效时，先重新登录，再核对 epoch。

### 3.8 托盘与窗口（Windows/Linux）
- 打开主窗口 / 新建笔记 / 立即同步 / 退出；关闭窗口默认「保存后隐藏到托盘」；菜单退出先 flush 成功再退出，无网络时不等待上传。
- Linux 托盘初始化失败或不确定可用性时，禁止静默隐藏窗口，退化为正常窗口 + 「关闭后退出」说明（PLATFORM-02）；Wayland / X11、fcitx / ibus 冒烟。
- 未登录时「立即同步」禁用并显示「仅本机」。

### 3.9 语言 / 外观 / 时区
- 简体中文 / English、浅色 / 深色 / 跟随系统，即时切换、重启有效、不改写正文 / 账号名 / 设备名 / 同步数据；深色界面无固定浅色大块。
- 时区默认 Asia/Shanghai（UTC+08:00），可选上海 / UTC / 系统；只改展示、不改存储 / 排序 / 协议 UTC 语义；不调整操作系统时区。

### 3.10 空间切换
- 本机 ↔ 已保存账号；切换前 flush；后台任务隔离（每个任务固定 profile_id / user_id，执行前复核）；注销 / 吊销 / 切空间不清 outbox；未经确认不把待发内容复制到其他账号（AUTH-04/05）。
- 跨服务器、跨账号不自动复制数据；同一服务器换域名不算同一空间；空间以「规范化 URL + user_id」隔离，不用用户名作隔离键。

### 3.11 数据库迁移
- 迁移前保全数据库、使用版本化脚本；升级含上版库（带待发、冲突、墓碑）完整保留；失败可回滚 / 恢复；高版本库旧应用只读提示升级、不自动降级（MIGRATION-01）。

### 3.12 性能与容量
- 1000 条 × 平均 2KiB：冷启动到可输入 P95 ≤2 秒；已提交笔记打开与常用搜索 P95 ≤200ms；无存储故障时输入到本地提交 ≤1 秒；记录样本数、设备与系统。
- 同步：两端前台、连接健康、单条修改 ≤64KiB 时，本地保存成功到另一端可见 P95 ≤5 秒；SSE 断开后兜底同步 ≤35 秒；后台 / 休眠 / 断网另测，不纳入 5 秒承诺。

## 4. 跨功能联动测试

1. 编辑 × 同步：同步期间持续输入不覆盖编辑缓冲区；拉取更新不抬高新草稿的 base_rev（SYNC-04）；本地保存失败时不能靠触发云请求绕过（core-api §3）。
2. 导入 × 同步：导入中崩溃后恢复，映射与待同步同事务；导入后立即同步 + 再次导入同代次 → 不重复、不跨账号复用映射。
3. 账号 × 同步：吊销后本地继续写 → 联网后 API / SSE 失效、内容仍在、重登继续；注销时有无网络 + 有待发内容的组合（AUTH-05）；切空间后旧任务回调不得写入新空间。
4. 恢复 × 账号 × 导入：epoch 轮换 + token 失效同时发生 → 先重登、再保全、再选择性导入，全程无静默覆盖。
5. 删除 × 冲突 × 恢复：删除后远端更新（edit_after_delete）；恢复后远端已更新（恢复也按冲突处理）；墓碑重复删除 already_deleted。
6. 导出 × 同步：导出前 flush、导出含已提交待发送内容；flush 失败时明确「部分内容尚未落盘」、不显示全部成功。
7. 托盘 × 保存：关闭窗口 → 隐藏前必须已 flush；保存失败时阻止常规退出并提供救援（不能丢内存内容）。
8. 搜索 × 删除：删除立即不在普通搜索出现、回收站可单独检索；索引与笔记同事务、崩溃后索引可重建。
9. 多设备收敛：三端同账号离线编辑 → 互相同步 → 最终可见状态一致（含冲突副本），无静默覆盖。
10. 协议演进 × 旧客户端：protocol_version 不支持 → 停止同步、提示升级、本地继续可用；v1 新增可选字段向后兼容。

## 5. 极限与边界用例

- 尺寸极限：正文恰好 1MiB / 1MiB+1 字节（NOTE_TOO_LARGE，不截断、保留救援、不阻塞其他笔记）；单条转义后必须能独立返回；Push 单批 50 条 / 51 条、8MiB / 8MiB+1（PAYLOAD_TOO_LARGE 拆批）。
- 标识与序号极限：UUID 碰撞（同 note_id 不同账号、同 note_id 不同内容走版本规则不覆盖）；rev / seq / cursor 64 位无符号（wire 必须十进制字符串，测试前导零与精度）；seq 严格递增、账号独立、无占位空洞。
- 并发极限：两设备对同一笔记反复交替编辑（多轮冲突）；同笔记并发删除 + 编辑 + 恢复；同 op 并发重试（幂等不重复）；同空间只允许一个同步协调器、前台 / 后台触发合并。
- 离线极限：长期离线累积大量 outbox 后一次性重连；离线新建又删除且从未发送（只留本地回收站，恢复后才建云笔记，SYNC-11）；创建请求已提交但响应丢失 + 本地删除 + 重启（SYNC-12）。
- 崩溃注入：写 notes 后、写 changes / processed_ops 前故障（SYNC-18）；拉取应用一页中注入崩溃（SYNC-14）；响应丢失后重试（SYNC-03）；Push 多事务中断只提交前缀后整体重试（SYNC-17）。
- 时钟与环境：设备时钟错乱导致列表顺序变化但不影响版本裁决；磁盘满 / 只读时保存、导出、迁移、退出的完整链路；系统凭据库不可用（LOCAL-04）。
- 输入法与文本：emoji、组合字符、超长单行、CRLF→LF 归一化、1MiB 边界的中文（UTF-8 多字节）；组合输入被同步更新 / 高亮打断的测试（EDIT-02）。
- 安全越权：跨账号 note / device / op / cursor 全部按「不存在」处理（AUTH-01）；日志 / 错误 / 限流不含正文、密码、邀请码、token；SSE 吊销后断开。
- 存储增长：changes / processed_ops / 墓碑在 v1 不裁剪 → 长期运行存储单调增长（已声明边界，需观察）。

## 6. 已知边界、极限与现存问题

### 6.1 硬边界（产品明确不支持或不保证）
- 正文 ≤1MiB UTF-8；单批 Push ≤50 项且 ≤8MiB；单条修改 ≤64KiB 才享 5 秒同步承诺。
- 无附件、无独立 Web / Apple、无全局快捷键 / 系统分享 / 开机自启 / 自动升级。
- 无永久删除、无自动清库、无自助删账号；v1 不裁剪 changes / processed_ops / 墓碑 → 存储单调增长。
- 搜索仅字面，无拼音 / 模糊 / 词义；FTS5 trigram 对少于三个字符的子串不匹配（靠回退兜底）。
- 无端到端加密（服务端可读正文）、本地库不加密（依赖操作系统账号与磁盘权限）。
- 令牌默认 90 天过期、无 refresh、重登需用户名密码；密码重置仅管理员（无邮件 / 短信）。
- 后台同步尽力而为：Android 周期任务最短 15 分钟、不承诺固定时刻；设备时钟不参与版本裁决（只影响展示顺序）。
- 本机导入是「复制」语义：导入后两端内容不再联动。

### 6.2 现存状态缺口（尚未实测，而非设计缺陷）
- v1 未发布：[本地验证](../docs/validation.md) 的三端发布清单均为未勾选；连续 7 天自用、1000 条性能实测、Linux 托盘 / 输入法实机、Android 后台实机均未完成——「边界在哪」目前尚无实测答案。
- 服务端 / core / 协议仍是 0.1.0 基线；客户端 0.1.3 只修正展示控件与滚动，不能把版本号当作 v1 发布。
- 强杀前未提交输入不承诺恢复；卸载 / 清数据会丢未同步内容——恢复手段仅靠导出与上线前备份。

### 6.3 优先补充顺序
1. 长期离线 outbox 积累 + 重连的收敛；
2. 1MiB / 8MiB / 50 条 / 1000 条容量边界实测；
3. 崩溃注入下的幂等与分页一致性（SYNC-14/17/18）；
4. 多设备多轮冲突收敛；
5. 吊销 / epoch 恢复 / 切空间三类身份变化下的 outbox 归属安全；
6. 磁盘满 / 只读 / 凭据库不可用的救援链路。
